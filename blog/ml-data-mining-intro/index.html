Machine Learning and Data Mining Basics: Model Families, Optimization, and Evaluation Discipline

An introductory guide to classical machine learning and data mining covering supervised and unsupervised model families, objective optimization, feature preparation, and leak-free evaluation.

Before turning to large neural networks, most structured data problems—tabular prediction, anomaly detection, customer segmentation, and sensor-feature modeling—are solved with classical machine learning (ML) and data mining methods. Knowing how these model families represent patterns, how their objectives are optimized, and how evaluation pipelines fail gives beginners a durable framework that carries directly into deep learning as well. This guide walks through the data-mining workflow, the main supervised and unsupervised algorithm families (linear models, nearest neighbors, support vector machines, decision trees and ensembles, clustering, and PCA), optimization and regularization principles, and leak-free evaluation metrics.

Readers interested in broader computer science and deep learning context can pair this guide with Computer Science Foundations and AI Basics. Small worked examples computed directly in the text are marked (computed).

The machine learning and data mining workflow

Data mining emphasizes the end-to-end process of turning raw records into reliable insights or predictions; machine learning supplies the statistical algorithms that fit models inside that pipeline.

flowchart LR
    R[Raw records & labels] --> C[Cleaning & EDA:<br/>missing values, outliers, types]
    C --> S[Split data first:<br/>train / validation / test]
    S --> F[Feature engineering:<br/>fit transforms on train only]
    F --> M[Model training & tuning:<br/>cross-validation]
    M --> E[Final held-out evaluation<br/>with task-aligned metrics]

Machine learning tasks fall primarily into two paradigms (with reinforcement learning, where an agent learns sequential policies from environment rewards, forming a third):

  • Supervised learning: Each training example pairs input features xxx with a known target yyy. Predicting a continuous value (house price, latency, temperature) is regression; predicting a discrete label (spam vs. legitimate, fault category) is classification.
  • Unsupervised learning: Only inputs xxx are available. The goal is to discover internal structure—grouping similar records (clustering), compressing correlated features (dimensionality reduction), or flagging unusual records (anomaly detection).

Supervised learning model families

Every model family encodes an inductive bias—a structural assumption about what kinds of relationships are easy for it to represent.

Linear models and regularization

Linear regression models a continuous target as a weighted sum y^=w⊤x+b\hat{y} = w^\top x + by^​=w⊤x+b by minimizing squared error. Logistic regression extends the same linear score to binary classification by passing z=w⊤x+bz = w^\top x + bz=w⊤x+b through the sigmoid function σ(z)=1/(1+e−z)\sigma(z) = 1 / (1 + e^{-z})σ(z)=1/(1+e−z) to output a probability in (0,1)(0, 1)(0,1), trained by minimizing binary cross-entropy (log loss).

When features are numerous or strongly correlated, unconstrained weights can grow huge to memorize noise. Regularization adds a penalty on weight magnitude to the loss:

  • L2 regularization (Ridge): adds λ∑jwj2\lambda \sum_j w_j^2λ∑j​wj2​, shrinking weights smoothly toward zero and stabilizing correlated features.
  • L1 regularization (Lasso): adds λ∑j∣wj∣\lambda \sum_j |w_j|λ∑j​∣wj​∣, driving weak feature weights to exact zero and performing automatic feature selection.

Distance-based and kernel methods

kkk-Nearest Neighbors (kkk-NN) performs no explicit parametric training: at prediction time it retrieves the kkk closest training points under a distance metric (such as Euclidean distance) and averages their targets or takes a majority vote. Because distance depends directly on feature scale, unnormalized features with large numeric ranges dominate the metric.

Support Vector Machines (SVMs) find the separating hyperplane that maximizes the margin—the distance to the closest points of each class (the support vectors). When classes are not linearly separable in raw coordinates, the kernel trick (such as an RBF Gaussian kernel) implicitly computes inner products in a higher-dimensional feature space without materializing that space explicitly.

Decision trees and ensemble methods

A decision tree partitions feature space recursively using axis-aligned splits (for example, age <= 30) chosen to make child nodes as pure as possible. For classification, a common impurity measure is the Gini index G=1−∑cpc2G = 1 - \sum_c p_c^2G=1−∑c​pc2​.

Suppose a node contains 4 positive and 4 negative examples (p+=p−=0.5p_+ = p_- = 0.5p+​=p−​=0.5): its Gini impurity is G=1−(0.52+0.52)=0.5G = 1 - (0.5^2 + 0.5^2) = 0.5G=1−(0.52+0.52)=0.5 (computed). If a candidate feature splits those 8 records cleanly into a left child (4 positive, 0 negative) (GL=0G_L = 0GL​=0) and a right child (0 positive, 4 negative) (GR=0G_R = 0GR​=0), the impurity reduction is ΔG=0.5−0=0.5\Delta G = 0.5 - 0 = 0.5ΔG=0.5−0=0.5 (computed), the maximum possible gain.

Single deep trees are easy to interpret and insensitive to feature scaling, but they overfit easily (high variance). Two ensemble strategies turn weak trees into the dominant algorithms for structured tabular data:

  • Bagging and Random Forests: Train many deep trees independently on bootstrap-resampled datasets while sampling a random subset of features at each split, then average their predictions. Averaging cancels individual tree variance.
  • Gradient Boosting (GBDT, e.g., XGBoost / LightGBM): Train shallow trees sequentially, where each new tree fits the negative gradient (residuals) left behind by the ensemble so far. Boosting steadily reduces bias and frequently achieves top accuracy on tabular benchmarks when tuned with learning rate, tree depth, and subsampling.

Unsupervised learning and data mining essentials

When labels are absent or expensive, unsupervised methods expose structure directly from features:

  • kkk-Means clustering: Alternates between assigning each sample to its nearest centroid and recomputing each centroid as the mean of its assigned points until assignments stabilize. It is fast and scalable, but requires choosing kkk ahead of time and assumes roughly spherical, similarly sized clusters.
  • DBSCAN (Density-Based Spatial Clustering): Groups points that have at least minPts neighbors within radius ε\varepsilonε, naturally discovering arbitrary non-spherical cluster shapes and labeling isolated points as noise/outliers without specifying the number of clusters in advance.
  • Principal Component Analysis (PCA): Projects correlated numeric features onto orthogonal axes (principal components) ordered by the fraction of variance they capture. Keeping the top components removes redundancy, speeds up downstream models, and supports 2D/3D visualization.

Optimization, loss functions, and the bias–variance trade-off

Fitting almost any parametric model minimizes an objective combining data-fit loss and regularization:

  • First-order vs. second-order solvers: Standard gradient descent (and mini-batch SGD / Adam) uses only first derivatives, scaling smoothly to millions of parameters. For smaller smooth problems such as nonlinear least squares, second-order methods (Newton, Gauss–Newton, L-BFGS) incorporate curvature information to converge in far fewer iterations.
  • Choice of loss: Squared error (ℓ2\ell_2ℓ2​) corresponds to Gaussian noise assumptions and penalizes large residuals heavily; absolute error (ℓ1\ell_1ℓ1​) and Huber loss behave linearly for large errors, making regression far more robust to outliers.
  • Bias–variance trade-off: A model that is too simple (e.g., fitting a straight line to curved data) suffers from high bias (underfitting)—both training and validation errors stay high. An overly flexible model memorizes training quirks and suffers from high variance (overfitting)—training error approaches zero while validation error climbs.

Feature engineering and leak-free evaluation

In practical data mining, feature quality and validation discipline usually move real-world performance more than swapping classifiers.

Core data preparation steps

  • Missing values: Distinguish missing-at-random entries from informative missingness; impute numeric features (median/mean or model-based) and add an explicit “was missing” indicator flag when absence carries signal.
  • Feature scaling and encoding: Standardize numeric columns (zero mean, unit variance) for linear models, kkk-NN, SVMs, and PCA; convert categorical variables with one-hot encoding (low cardinality) or target/ordinal encoding carefully inside cross-validation folds.
  • Preventing data leakage: Never fit scalers, imputers, or feature selectors on the full dataset before splitting. Statistics computed on validation or test rows leak future information into training and inflate validation scores artificially.

Choosing splits and metrics that match the task

Random shuffling works only when rows are independent and identically distributed. Two common exceptions require structured splits:

  • Grouped data (multiple records from the same user, patient, or sensor route): use Group KKK-Fold so the same entity never appears in both train and validation.
  • Time-series data: always split chronologically (train on past, validate on future) so the model cannot peek ahead.

Similarly, plain accuracy can mislead severely under class imbalance. Suppose 1,000 transactions contain 10 frauds (1%). A trivial model predicting “normal” for every transaction reaches 99.0% accuracy while catching 0 frauds (computed). Suppose a real detector flags 12 transactions, 8 of which are truly fraud:

  • Precision =812≈66.7%= \frac{8}{12} \approx 66.7\%=128​≈66.7% (computed) — of flagged alerts, how many are genuine;
  • Recall =810=80.0%= \frac{8}{10} = 80.0\%=108​=80.0% (computed) — of all real frauds, how many were caught;
  • F1 score =2×Precision×RecallPrecision+Recall=1622≈72.7%= \frac{2 \times \text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{16}{22} \approx 72.7\%=Precision+Recall2×Precision×Recall​=2216​≈72.7% (computed) — harmonic mean balancing both.

For probability-ranking tasks across thresholds, ROC-AUC and PR-AUC (especially PR-AUC for rare positives) summarize discrimination far better than accuracy at a single cutoff.
