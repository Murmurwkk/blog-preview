Attention Sinks and Output Gates: How a Head Outputs Nothing

This note explains why a softmax head cannot scale its own output, and how attention sinks and output gates let it output almost nothing. With it, a reader can tell when the two mechanisms are equivalent.

An attention head outputs a weighted average of its values, so it cannot make its own output smaller. Two published mechanisms give a head a way to output almost nothing. An attention sink is a position whose value is close to zero, and StreamingLLM keeps the first positions of the KV cache because such sinks live there. Qwen’s Gated Attention instead multiplies the output of each head by a coefficient computed from the current input.

This note starts with the constraint of convex combinations and a worked example. It then examines what each mechanism does in its source code, and it derives exactly when a zero-value sink and an output gate are equivalent and when they are not. My own checks run on CPU: the authors’ cache class and an extracted attention function, without model weights and without training. The text describes these checks as verifications, and the appendix gives their code versions and commands.

Why a head cannot output nothing

Give every value in one attention head the scalar 1. However the queries and keys change, and wherever softmax puts its probability, the weighted sum is always exactly 1. The head can decide where its content comes from, but it cannot shrink its own output: it cannot make the output 0.1, and it cannot write nothing at all.

Adding one position whose value is 0 solves this problem. If 90% of the probability goes to this position, the output becomes 0.1. On an attention heatmap this position takes most of the weight, yet it writes 0 into the result; what it really changes is the contribution of every other position.

This construction only shows what kind of computation a sink can perform, and it does not prove that every model needs one. The same constraint appears in two practical places, and each place has its own solution:

  • On the cache side: when the KV cache has a fixed length, the earliest positions are evicted. If an evicted position was a sink, the remaining content is scaled up all at once. For this reason, StreamingLLM keeps the first few positions permanently: four by default in its code, and two in the experiment below.
  • On the architecture side: Qwen’s Gated Attention inserts a coefficient computed from the current input after SDPA and before the output projection, and this coefficient directly shrinks the output of the whole head.

The two mechanisms act in different places. Removing a sink redistributes the shares inside the denominator of softmax, so the other positions receive more probability and the remaining content is amplified. Output gating acts later: it multiplies the finished vector by a coefficient below 1 and leaves the proportions between the contents unchanged.

Fundamentals: scores, probabilities and outputs are different things

Let the input hidden state of the current position be xix_ixi​, projected to a query qiq_iqi​, and let the historical positions provide keys kjk_jkj​ and values vjv_jvj​. Without positional encoding and mask details, one head computes

sij=qikj⊤dh,pij=esij∑kesik,ui=∑jpijvj.s_{ij}=\frac{q_i k_j^\top}{\sqrt{d_h}}, \qquad p_{ij}=\frac{e^{s_{ij}}}{\sum_k e^{s_{ik}}}, \qquad u_i=\sum_jp_{ij}v_j.sij​=dh​​qi​kj⊤​​,pij​=∑k​esik​esij​​,ui​=j∑​pij​vj​.

Here dhd_hdh​ is the width of the head. The uiu_iui​ of several heads are concatenated, passed through the output projection WOW_OWO​ and written into the residual branch. So there are three distinct objects: the scores sss that express preference, the normalized probabilities ppp, and the vector uuu that actually enters the later computation. Heatmaps usually show only the middle object.

Since pij≥0p_{ij}\ge0pij​≥0 and the probabilities sum to 1, uiu_iui​ always lies in the convex hull of the vjv_jvj​: the region reachable by mixing these vectors with non-negative weights that sum to 1. If every value is 1 in some dimension, the output in that dimension can only be 1. When a zero vector is added, the origin joins the hull, and the output gains room to shrink.

Real models have other options as well: values can cancel each other, WOW_OWO​ can change direction and scale, and the residual branch can adjust together with other sublayers.

StreamingLLM observed that several trained models repeatedly assign large attention to the initial positions, and it connected this behavior to probability normalization and to the fact that every later query can see the initial positions. When Attention Sink Emerges further examined the conditions in training and architecture. In its setting, a sink acts more like a key bias that absorbs excess probability, and the normalization scheme affects how the sink forms.

Because the initial positions are always visible, they are suitable for this role, but whether a sink actually forms still depends on the learned keys, the values and the training. A large key norm is not enough to diagnose a sink, and a high attention weight does not show semantic importance. To see the influence on later computation, the value must be multiplied in.

Dropping a sink changes the whole row’s normalization

Fix one query. Let a candidate sink have probability aaa and value vsv_svs​, and let μ\muμ be the output of the other positions after they are renormalized among themselves. The full result is

u=avs+(1−a)μ.u=a v_s+(1-a)\mu.u=avs​+(1−a)μ.

If only this position is dropped and every other logit and value stays unchanged, the result becomes μ\muμ, so

udrop−u=a(μ−vs).u_{\mathrm{drop}}-u=a(\mu-v_s).udrop​−u=a(μ−vs​).

The opening example with vs=0v_s=0vs​=0 is a special case. When μ≠0\mu\ne0μ=0, the magnitude after dropping is 1/(1−a)1/(1-a)1/(1−a) times the original magnitude: a=0.9a=0.9a=0.9 gives 10×, and a=0.99a=0.99a=0.99 gives 100×.

Figure 1: Amplification after dropping a zero-value sink, computed directly from declared scalar inputs; this isn’t a measured 100× amplification in a language model.

As a check of the general formula, three random seeds, four value dimensions and eight probabilities gave 96 FP64 computations with a maximum absolute residual of 8.88×10−168.88\times10^{-16}8.88×10−16.

The direct content contribution of the dropped position can be tiny while its share of the denominator is huge, and after the position is dropped, all remaining content is scaled up together. This identity describes one row of one attention call. Inside a full Transformer, the downstream inputs also change, so these row differences cannot simply be added up into a final model error.

StreamingLLM: keep two pieces of the cache

Autoregressive generation keeps accumulating historical KV. The simplest policy with a fixed length keeps only a recent window and evicts the oldest entries once the window is full. If the initial positions happen to act as sinks, the normalization change from the previous section occurs the first time these positions slide out of the window.

StreamingLLM keeps two pieces of the cache: a few initial KVs and a recent stretch. It does not compress the whole history, and it does not estimate a retention value for each old token; the initial positions are always kept, and everything in the middle is dropped.

The core of the key selection in the authors’ StartRecentKVCache is only this:

torch.cat(
    [
        self.k_slice(k, 0, self.start_size),
        self.k_slice(k, seq_len - self.recent_size, seq_len),
    ],
    dim=self.k_seq_dim,
)

The values are sliced in the same way. If the sequence has not exceeded the capacity, the cache is returned unchanged, and only after that point are the two pieces concatenated. With start_size=2, recent_size=14, the cache keeps 16 positions, and two of them are permanently reserved for the start. Compared with a pure sliding window, this setting keeps two fewer recent tokens.

I fed tensors numbered 0–63 into this real cache class one after another, under both 0+16 and 2+14. In all 128 CPU calls, the kept indices matched the rule. These indices were then applied to two constructed attention inputs, and the two inputs show both the benefit and the cost of the same rule.

The lower half of the figure switches to retrieval. Only token 10 has the value 1 and the logit 8, and every other value is 0, so the output equals the probability of the target token. Both results hold at the same time. Keeping the initial KVs makes the already-learned normalization behavior more continuous, and the cost is less room for recent content. So the streaming ability of StreamingLLM does not mean that the model can still retrieve information from the dropped history.

Cache positions have to match RoPE

A real implementation cannot stop at these two slices. RoPE encodes position as a rotation of queries and keys, so the dot product depends on the relative position. After a stretch of middle tokens is dropped, the kept KVs can only use contiguous cache positions if the implementation knows exactly where the rotation is applied.

In the authors’ Llama position-shift implementation, the cache receives the unrotated key, and only the key used for the current attention call is rotated by contiguous positions:

past_key_value = (key_states, value_states) if use_cache else None

key_position_ids = torch.arange(kv_seq_len, device=position_ids.device).unsqueeze(0)
key_states = apply_rotary_pos_emb_single(key_states, cos, sin, key_position_ids)

For example, if the kept history tokens are [0, 1, 2, 3, 6, 7, 8] and the next query is token 9, the computation uses positions organized by the cache. Dropping the middle gap changes the relative distance between the start and the recent content, so it is neither a uniform shift of every position nor just a movement of memory.

If the cache stored keys that were already rotated by their old positions, a second rotation by the new positions would stack two rotations. So the key ordering in this code is to cache unrotated keys and let each computation generate the rotations for the current positions.

Gated attention: scaling after the weighted sum

The architecture side offers a more direct approach. One of the gating positions studied in Gated Attention sits directly after the SDPA output and before the output projection.

Let the pre-norm hidden state of the current query be xix_ixi​, and let the head output still be ui=∑jpijvju_i=\sum_jp_{ij}v_jui​=∑j​pij​vj​. A gate is generated from the same xix_ixi​:

gi=σ(xiWG),u~i=ui⊙gi.g_i=\sigma(x_iW_G),\qquad \widetilde u_i=u_i\odot g_i.gi​=σ(xi​WG​),ui​=ui​⊙gi​.

A headwise gate gives the whole head one coefficient, while an elementwise gate generates one coefficient for each channel within the head. Both gates take effect only after the softmax of this call is finished, so neither gate redistributes the pijp_{ij}pij​ of this call. The heads are concatenated and passed through WOW_OWO​ afterwards.

The authors’ pinned Qwen3Attention source folds the gate projection into the same q_proj as the query projection. In the elementwise version, the output is twice as wide as an ordinary query and is then split into query and gate by KV group, and the final shape of the gate is [batch, length, heads, head_dim].

This folding only merges two linear projections; it does not mean that the gate takes part in the QK dot product. The query that is split off builds the attention probabilities as usual, and the gate branch waits until this point:

attn_output = attn_output.transpose(1, 2).contiguous()

if self.headwise_attn_output_gate or self.elementwise_attn_output_gate:
    attn_output = attn_output * torch.sigmoid(gate_score)

attn_output = attn_output.reshape(bsz, q_len, -1)
attn_output = self.o_proj(attn_output)

The position of this multiplication in the code determines both the broadcast and the meaning of the channels. Moving a per-channel gate after WOW_OWO​ generally does not give the same result, because the output projection has already mixed the channels, and a matrix multiplication does not commute with an arbitrary diagonal scaling.

To observe only this one property, I extracted the eager forward function from the pinned source and ran it with small projection layers on CPU. With Q/K/V held identical and headwise and elementwise gates added separately, over sequence lengths 1, 7 and 16 and seeds 0, 17 and 42, the test made 18 comparisons. The returned attention probabilities differ by exactly zero, and the outputs exactly match an independent reconstruction of “original SDPA output times the corresponding gate”.

This is a check of the forward mechanism. The paper reports that sinks become weaker in gated models after training, and this result involves Q/K and intermediate activations that change during training. Section 4 of the paper connects this result with output sparsity that depends on the query and differs between heads. Multiplying a gate into a model with fixed weights does not reproduce this training result. In this eager implementation, the gate also saves no QK or PV computation, because SDPA is already finished when the multiplication happens.

When is a zero-value sink the same as a gate?

The output of 0.1 from the opening example can be produced by a zero-value sink that holds 90% of the probability, or by multiplying the ordinary output by 0.1. For one fixed query, the two methods can indeed match exactly.

Let the exponent sum of the ordinary positions be Z=∑jesjZ=\sum_j e^{s_j}Z=∑j​esj​ and their self-normalized output be μ\muμ. Add a sink with logit ccc and value zero:

usink=ZZ+ecμ.u_{\mathrm{sink}}=\frac Z{Z+e^c}\mu.usink​=Z+ecZ​μ.

For this output to equal gμg\mugμ from a scalar gate with 0<g<10<g<10<g<1, it is enough to choose

c=log⁡Z+log⁡1−gg.c=\log Z+\log\frac{1-g}{g}.c=logZ+logg1−g​.

The cases g=0g=0g=0 and g=1g=1g=1 correspond to limits with an infinite logit. The key detail is that ZZZ appears in the matching value: if the ordinary keys and the query change, the required sink score also changes.

Where they diverge: a common logit offset

Add the same offset bbb to every ordinary logit. The softmax distribution among the ordinary tokens does not change, and μ\muμ does not change either, but ZZZ is multiplied by ebe^beb. So a sink with a fixed logit changes its scaling, while a fixed output gate does not.

The output of the fixed sink with c=0c=0c=0 moves from near zero toward 1, while the output of the fixed gate with g=0.2g=0.2g=0.2 stays at 0.2. The sink matched to each input with the formula above differs from the gate by at most 1.94×10−161.94\times10^{-16}1.94×10−16.

The score of a real sink does vary with the query, so it is not necessarily constant. Whether the dot product of a fixed key with the query can produce log⁡Z+log⁡((1−g)/g)\log Z+\log((1-g)/g)logZ+log((1−g)/g) for every input, however, still needs a proof, because ZZZ aggregates the exponent scores of all ordinary keys. Computing a ccc by hand for each input does not establish a general equivalence between the two parameterizations.

Where they diverge: per-channel scaling

An elementwise gate changes another condition, because a zero-value sink can only scale all channels uniformly. If the ordinary output is

μ=(1,1.118615),\mu=(1,1.118615),μ=(1,1.118615),

then every scalar gate produces a point on the line gμg\mugμ. The per-channel coefficients (0.2,0.8)(0.2,0.8)(0.2,0.8), however, give

μ~=(0.2,0.894892).\widetilde\mu=(0.2,0.894892).μ​=(0.2,0.894892).

The direction has changed: the best-fitting scalar is about 0.533487, and the remaining Euclidean distance is still about 0.447317.

If all logits and values could be retrained, the reachable set would change, so the distance in the figure is not a proof about the expressiveness of every attention parameterization.

What gating adds to the value path can be written out through the projections. With the current attention weights fixed,

(∑jpijxjWV)WO=∑jpijxj(WVWO).\left(\sum_jp_{ij}x_jW_V\right)W_O =\sum_jp_{ij}x_j(W_VW_O).(j∑​pij​xj​WV​)WO​=j∑​pij​xj​(WV​WO​).

The ordinary value projection and output projection can be merged into one matrix. When a per-channel gate introduces a diagonal matrix DiD_iDi​ that depends on the query, the merged term becomes

WVDiWO.W_VD_iW_O.WV​Di​WO​.

So different queries can make different choices among the same value channels, and what gating adds is a transform that depends on the input. Full attention already depends nonlinearly on the input through Q/K and softmax, so gating is not “the first nonlinearity”. In addition, for a fixed query, the rank of this product still cannot exceed the width of the head, and adding a diagonal matrix does not break this bound.

Conclusion

Softmax makes the output of a head a convex combination of its values. A head that needs to write less therefore needs either a value near zero that absorbs probability (a sink) or a way to scale the output afterwards (a gate). The three operations in this post use different inputs:

  • A sink changes how much share the other content receives inside the probability normalization, and it looks only at the scores of the current forward pass.
  • An output gate adjusts heads or channels after the content is aggregated, and it also looks only at the current weights.
  • StreamingLLM decides which positions stay in the cache.

The two schemes can coexist. Both reduce some form of the sink phenomenon, but this does not mean that two cache positions can simply be replaced by one multiplication.

A sink and a gate can produce the same number for one query, but they are different mechanisms as soon as the inputs change.

Environment and measurement method

Author-function checks use CPU PyTorch 2.14.1; curves use Python 3.13.5, NumPy 2.4.4 and Matplotlib 3.11.0. No model weights were downloaded, no GPU benchmarks run and no language model trained. StreamingLLM is MIT licensed; Gated Attention’s root is MIT, the excerpted file keeps its Apache-2.0 header, and the snapshot keeps both attributions.

In the gating comparison, RoPE is the identity rotation, dropout is zero, the causal mask is kept and WOW_OWO​ is the identity so head output can be read directly. Projections and multiplies use FP64, with softmax converted to FP32 and back as in the authors’ implementation. That’s nine base forward passes plus eighteen gated ones, not full Qwen model inference.
