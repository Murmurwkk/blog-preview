A Feature You Can Name Is Not a Circuit

Sparse autoencoders made features cheap to name, but naming one doesn't show the model uses it. How interpretability went from circuits to dictionaries and back to computation graphs.

草稿 · 更新于 2026/11/7 · 7 个章节
#interpretability#sparse autoencoders#mechanistic interpretability#circuit tracing#TransformerLens#Anthropic

Interpretability research can now name millions of features inside a production language model. Scaling Monosemanticity extracted about 34 million from Claude 3 Sonnet, and clamping just one, the Golden Gate Bridge feature, steered nearly every answer toward the bridge. Yet a named feature, on its own, is not evidence that the model uses it to produce an answer. When Anthropic later traced how Claude 3.5 Haiku actually adds 36 + 59, the computation ran through two parallel paths. When the model was asked how it got 95, it described the textbook carry method instead.

That gap, between a direction you can label and a computation you can show, is the thread of this post. The field started with circuits, switched to dictionaries of features when circuits stopped scaling, and is now going back to circuits with those dictionaries in hand. Sparse autoencoders (SAEs) sit in the middle of that arc: they made “feature” a measurable object, and their limits pushed the field toward attribution graphs and language-based readouts.

Here’s the route. First, the history, told as the question each step answered and the one it left open. Second, what an SAE is today, down to the tensors, the sparsity mechanisms and the training loop in SAELens. Third, the methods that put features back into a computation: attribution graphs, crosscoders, natural-language autoencoders, the workspace paper and the J++ lens. Last, what’s still open, and what this post does and doesn’t show.

Circuits: the residual stream as a shared channel

A Mathematical Framework for Transformer Circuits starts from an architectural fact. Every transformer block adds its output to a residual stream, and every later block reads from that same sum. So the whole model can be rewritten as a sum of paths: the embedding straight to the output, the embedding through one attention head, through two heads in sequence, and so on.

flowchart TD
    E["token embedding"] --> R1(("residual stream"))
    R1 --> H1["layer 1 heads"]
    H1 -- "add output" --> R2(("residual stream"))
    R1 --> R2
    R2 --> H2["layer 2 heads"]
    H2 -- "add output" --> R3(("residual stream"))
    R2 --> R3
    R3 --> U["next-token logits"]

Figure 2: Blocks read from and add to one shared stream, so the model’s output is a sum over paths through the blocks.

Each attention head then factors into two parts. The QK circuit, WQ⊤WKW_Q^\top W_KWQ⊤​WK​, decides which earlier positions a token attends to. The OV circuit, WOWVW_O W_VWO​WV​, decides what gets copied from there into the stream. A “circuit” is a path through such matrices that implements a behavior. Two conventions from this paper still hold: the residual stream is a communication channel that every layer reads and writes, and the natural unit is a direction in it, not a neuron. The paper worked out zero-, one- and two-layer attention-only models exactly; it didn’t say how to find circuits in a 70-layer model.

In-context Learning and Induction Heads supplied the first convincing circuit. An induction head looks for the previous occurrence of the current token and copies the token that followed it. It needs a partner: a previous-token head writes “the token before me” into the stream, and the induction head uses that to find the match. The paper backed this with six independent lines of evidence, among them a phase change in training where induction heads appear just as in-context learning improves, and ablations that remove the heads and the ability together. Mechanism, intervention and training story became the template for later work.

Superposition: why neurons are the wrong unit

Toy Models of Superposition explained why reading individual neurons fails. The toy model squeezes nnn features through m<nm<nm<n hidden dimensions and back, with a ReLU at the output. When features are dense, it keeps only the most important ones, each in its own dimension, and drops the rest. Once features are sparse enough, it packs extra features into shared, non-orthogonal directions, because two rarely-active features seldom collide. The packed features settle into regular shapes, such as antipodal pairs, triangles and pentagons, depending on how often each feature is active and how much it matters.

Figure 3: Five features in two dimensions. Dense features get their own axes and the rest are dropped; sparse features share the space at the corners of a pentagon.

Once superposition is real, “find the neuron for X” is the wrong question. The right one is “find a sparse set of directions whose combination reconstructs the activation”, which is a dictionary-learning problem, and exactly what an SAE solves.

Dictionaries: making “feature” measurable

Towards Monosemanticity ran the first serious SAE on a language model: a one-layer transformer with a 512-neuron MLP, and dictionaries from 512 up to 131,072 latents (the main analysis used 4,096, eight times overcomplete). The learned latents were often interpretable, wider dictionaries split features into finer ones, and the paper set up evaluation habits still in use: activation examples, logit effects and ablations.

Scaling Monosemanticity took the same instrument to Claude 3 Sonnet, with dictionaries of 1, 4 and 34 million features. The features were multilingual, some responded to images as well as text, some were safety-relevant, and clamping them changed behavior coherently.

That also set up the current debate. A feature that fires on the Golden Gate Bridge is interpretable. Whether the model uses it when it answers a question about bridges is a separate claim, and steering experiments are the start of that evidence, not the end.

Graphs and language: putting features back into the computation

A dictionary says which directions exist, not which ones were used, in what order, to produce a given token. On the Biology of a Large Language Model is the bridge back to circuits. It builds a replacement model for Claude 3.5 Haiku, traces individual outputs through it, and finds computations the model’s own text doesn’t mention. The method is in Attribution graphs below.

The latest work attacks the same gap from the output side: if features are hard to name, can the model’s activations be explained in language, by the model or by a trained translator? That’s the second half of this post’s frontier.

What an SAE is today

The object

An SAE is an autoencoder whose hidden layer is much wider than its input. For an activation x∈Rdinx\in\mathbb{R}^{d_{\text{in}}}x∈Rdin​:

z=act⁡(Wex+be),x^=Wdz+bd,z=\operatorname{act}(W_e x+b_e),\qquad \hat{x}=W_d z+b_d,z=act(We​x+be​),x^=Wd​z+bd​,

with We∈Rdsae×dinW_e\in\mathbb{R}^{d_{\text{sae}}\times d_{\text{in}}}We​∈Rdsae​×din​, Wd∈Rdin×dsaeW_d\in\mathbb{R}^{d_{\text{in}}\times d_{\text{sae}}}Wd​∈Rdin​×dsae​ and dsae≫dind_{\text{sae}}\gg d_{\text{in}}dsae​≫din​. Training minimizes reconstruction error plus a sparsity cost:

L=∥x−x^∥22+λ S(z).\mathcal{L}=\lVert x-\hat{x}\rVert_2^2+\lambda\,S(z).L=∥x−x^∥22​+λS(z).

The interesting part is SSS. With the L1 norm, the model pays per unit of activation, so active coefficients get shrunk toward zero. With a count of active latents, it pays per latent and the coefficients themselves go unpenalized. With a learned threshold, the line between active and inactive becomes a parameter. I derived these objectives on a toy problem in an earlier post; the short version is that L1 shrinks, TopK truncates and JumpReLU thresholds.

Two details matter in code.

TopK caps the count; it doesn’t fix it. SAELens selects the kkk largest pre-activations, applies ReLU to them, and scatters them back (abbreviated from the source):

topk_values, topk_indices = torch.topk(x, k=self.k, dim=-1, sorted=False)
values = topk_values.relu()
result = torch.zeros_like(x)
result.scatter_(-1, topk_indices, values)

A token with fewer than kkk positive pre-activations therefore ends up with fewer than kkk active latents. BatchTopK relaxes the cap further, choosing the top k×k\timesk×batch activations across a whole batch so that easy tokens use fewer latents and hard ones more.

JumpReLU needs a gradient for its threshold. The forward pass is a step, whose gradient is zero almost everywhere. The JumpReLU paper replaces it with a rectangle kernel KKK of width www (the bandwidth) around the threshold. For the activation z=u⋅1[u>θ]z=u\cdot\mathbf{1}[u>\theta]z=u⋅1[u>θ] and for the L0 penalty 1[u>θ]\mathbf{1}[u>\theta]1[u>θ], the pseudo-derivatives with respect to θ\thetaθ are

while the input’s gradient passes straight through wherever the gate is open. SAELens implements both as custom torch.autograd.Functions, JumpReLU and Step, with exactly these factors.

The training loop

flowchart TD
    A["corpus"] --> B["model forward pass"]
    B --> C["hooked activation x"]
    C --> D["normalize and batch"]
    D --> E["encoder: W_e x + b_e"]
    E --> F["sparsity gate"]
    F --> G["latents z"]
    G --> H["decoder: W_d z + b_d"]
    H --> I["loss: reconstruction + sparsity"]
    I --> K["optimizer step and dead-latent fixes"]
    K -.-> E

Figure 5: One SAE training run; the dotted arrow is the next batch. The gate is L1, TopK or JumpReLU; evaluation (CE loss recovered, L0, auto-interpretability) runs on the trained dictionary.

A modern run stacks five loops. None is mathematically deep, and all of them change the result.

  1. Collect activations. A hook captures the residual stream, an MLP output or an attention output over a large corpus, cached and shuffled. Normalization matters: if activation norms drift between batches, the SAE can learn a norm-dependent dictionary. SAELens offers none, expected_average_only_in, constant_norm_rescale, layer_norm and covariance_whitening.

  2. Initialize. Decoder columns are scaled to a fixed norm (decoder_init_norm, 0.1 by default), the encoder starts as the decoder’s transpose, and the decoder bias starts at zero. Without a fixed decoder norm, the optimizer can cheat the L1 penalty by shrinking latents and growing decoder columns.

  3. Optimize. Adam with warmup and decay, with batches counted in tokens, since each token yields one activation vector. The GPT-4 SAE in the TopK paper saw 40 billion tokens.

  4. Keep latents alive. A latent is “dead” if it hasn’t fired for a window of steps; dead latents waste capacity and distort sparsity statistics. SAELens tracks them with a counter:

    def dead_neurons(self) -> torch.Tensor:
    return (self.n_forward_passes_since_fired > self.cfg.dead_feature_window).bool()

    Three fixes are in use. AuxK (from the TopK paper) adds a loss that lets the top dead latents reconstruct the residual error, so they get gradient. A pre-activation loss (Anthropic’s JumpReLU recipe) pushes dead latents back toward their threshold. Resampling reinitializes dead latents toward poorly reconstructed inputs; it’s common in older L1 recipes.

  5. Evaluate. Reconstruction alone isn’t enough: in the earlier post’s experiment, a wider dictionary reconstructed better while recovering fewer of the true directions. The usual suite is CE loss recovered (splice the reconstruction into the model and see how much next-token loss survives), L0, the dead-latent fraction, auto-interpretability (a model names a feature from its examples, and the name is scored), sparse probing and causal interventions. SAEBench bundles these across hundreds of public SAEs, because most papers had optimized one proxy at a time.

The hook

TransformerLens supplies the plumbing. A HookPoint is an identity module at a named site:

def forward(self, x: Tensor) -> Tensor:
    return x

A hook function registered there can cache the activation for training, or return a replacement, such as an SAE’s reconstruction, at inference. SAELens’s HookedSAETransformer.add_sae(sae) wires an SAE to its hook name and can keep the reconstruction error as a separate term, so the model’s output is unchanged even though the SAE is imperfect.

The hook name is part of the interpretation. blocks.5.hook_resid_pre and blocks.5.hook_attn_out have the same shape but are different objects: one is the stream entering the block, the other is what attention adds to it. A dictionary trained at one site doesn’t transfer to another just because the shapes match.

Putting features back into the computation

The methods below try to answer what a dictionary can’t: which features take part in this computation, in what order, and does the model’s own account match?

Attribution graphs

On the Biology of a Large Language Model traces outputs of Claude 3.5 Haiku through a replacement model with three ingredients:

  1. A cross-layer transcoder replaces the MLPs. It has about 30 million features, each reading from the residual stream at one layer and writing to the MLP outputs of that and later layers. A transcoder models the MLP’s function, input to output, rather than just reconstructing an activation, which is what circuit work needs.
  2. Attention stays as it is. For a given prompt, the original model’s attention patterns and normalization are frozen, which makes the rest of the replacement linear.
  3. Error nodes hold what the replacement misses at each position, so the trace is honest about its gaps.
flowchart TD
    T["prompt tokens"] --> F1["transcoder features, early layers"]
    F1 -- "frozen attention moves information between positions" --> F2["transcoder features, later layers"]
    F2 --> O["output logit for the target token"]

Figure 6: An attribution graph. With attention frozen, each feature’s influence on the target logit can be traced backward exactly. Error nodes, not drawn, sit beside the features and hold what the replacement misses.

Because the replacement is linear given the frozen attention, the influence of every feature on a target logit can be computed directly, giving a graph from input tokens through features to the output. The case studies show structure the text doesn’t:

  • Poems: the model picks the rhyming word before it writes the line that ends with it.
  • Hallucination: “can’t answer” features are on by default, and features for known entities switch them off. A hallucination happens when a familiar name switches them off although the model doesn’t know the answer.
  • Addition: the model computes the sum’s rough size and its last digit along separate paths and combines them, but describes the carry method when asked.

The limits are equally concrete. The replacement is an approximation, and its error nodes are uninterpretable. A graph explains one output, not the model. And the method needs a trained transcoder plus an attribution pass per prompt.

Crosscoders

A crosscoder reads and writes several layers, or several models, with one dictionary. If superposition spreads a feature across layers, a single-layer dictionary only sees a slice of it; a crosscoder can follow it as it persists through the stream, or find which features fine-tuning added or removed. The 2024 note is explicitly preliminary, a direction rather than a finished method.

Language as the readout

Three recent results turn interpretation into translation.

Introspection. Emergent Introspective Awareness injects a concept directly into a model’s activations and asks whether it notices anything. Models sometimes report the injected concept, and sometimes modulate an internal state on request, but unreliably and depending on the task.

Natural language autoencoders. An activation verbalizer turns an activation into text, and an activation reconstructor turns the text back into an activation. Both start from the target model and are trained jointly with reinforcement learning: the verbalizer is rewarded when its text lets the reconstructor recover the activation.

    V --> T["explanation in plain text"]
    T --> R["activation reconstructor (an LLM)"]
    R --> A2["reconstructed activation"]
    A2 --> L["error against the original activation"]
    L -. "RL reward" .-> V

Figure 7: A natural language autoencoder. Language is the bottleneck, so the code is readable by construction.

Nobody supervises the explanations to be interpretable; they get more informative as reconstruction improves. In a pre-deployment audit of Claude Opus 4.6, NLAs surfaced evaluation awareness the model never put into words, and agents equipped with them beat baselines on an automated auditing benchmark. The paper is candid about the limits: explanations can confabulate specifics, the verbalizer can infer more than the activation holds, and training means reinforcement learning on two full LLMs.

The workspace paper. Verbalizable Representations Form a Global Workspace introduces the Jacobian lens (J-lens), which finds the representations a model is poised to put into words, and argues they form a workspace. This “J-space” sits in a middle band of layers, has limited capacity (most features lie outside it), and supports verbal report, directed modulation and multi-step reasoning: ablating its top directions damages multi-hop reasoning while leaving tasks like classification largely intact. In auditing, strategic content showed up there even when absent from outputs. And training a model to state its principles when interrupted, which the paper calls counterfactual reflection training, improved its uninterrupted behavior, with the gain largely reverting when the implanted representations were ablated.

The J++ lens

The J-lens reads out intermediate concepts with one linear map per layer, built by averaging Jacobians over many token positions. The J++ lens, from the October 2026 circuits update, clusters each layer’s activations and fits a Jacobian per cluster. It combines them with learned weights that mostly discard poor clusters, uses layerwise relevance propagation from the R-lens, and filters spurious tokens. It’s still one linear map per layer, a drop-in replacement, and it surfaces intermediate variables more reliably than either earlier lens. The update presents it as preliminary.

What’s still open

Five problems are live, and none is solved by a bigger dictionary.

  1. Feature absorption. A specific feature can be absorbed into a more general one, so the SAE reconstructs well with no dedicated latent for the specific concept. The dictionary looks complete and isn’t. Matryoshka SAEs, which train nested dictionaries of increasing size together, are one response.
  2. Evaluation. Reconstruction, L0, dead latents, auto-interpretability and causal effect measure different things and trade off against each other. A method can improve one and worsen another without saying so.
  3. Faithfulness. An attribution graph is a hypothesis about a computation; a natural-language explanation is a hypothesis about a representation. Neither is guaranteed to match the mechanism, and the addition case shows a model’s own account can diverge from its computation.
  4. Scale. A 34-million-feature dictionary is already large, and a graph over every layer of a production model is larger. The cost of interpretation now limits how often it can be done.
  5. Necessity. If graphs can trace a circuit through transcoders and NLAs can explain an activation without a dictionary, what is the SAE for? The honest answer is a labeling layer: it gives nodes names and a shared vocabulary. That’s valuable, and it isn’t the same as being the explanation.

What this does and doesn’t show

  • It shows how the central object moved from circuit to feature to graph, and why each move happened.
  • It shows what an SAE is in code: the tensors, the three sparsity gates, initialization, dead-latent handling and the hook that connects it to a model, checked against the SAELens source.
  • It shows what each recent method can and can’t claim: attribution graphs, crosscoders, natural language autoencoders, the workspace paper and the J++ lens.
  • It doesn’t report new measurements. I didn’t train an SAE or trace a circuit for this post; every number comes from the cited papers.
  • It doesn’t compare the methods on a common benchmark; none covers all of them.
  • It doesn’t claim any explanation is faithful. The argument is the opposite: each method yields a hypothesis, held to a different standard of evidence.

Conclusion

The field began by decomposing weights into circuits, found that neurons are the wrong unit, built dictionaries of directions, and then discovered that a dictionary isn’t a computation. The newest work is the return trip: put features back into a graph, or translate activations into language, and check that the model’s behavior follows.

Naming a feature is a measurement; showing the model uses it takes an intervention, a graph or a causal test, and the SAE made only the first one cheap.
