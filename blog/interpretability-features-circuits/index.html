Interpretability from Circuits to Features and Back to Circuits

This note follows interpretability from circuits to sparse-autoencoder features and back to computation graphs. With it, a reader can tell what an SAE measures and which methods show that a model uses a feature.

Mechanistic interpretability tries to explain the answers of a language model through its internal computation. Its central unit has changed twice. The field started with circuits, switched to dictionaries of features when circuits stopped scaling, and is now going back to circuits, with those dictionaries as tools. Sparse autoencoders (SAEs) sit in the middle of this history: they made “feature” a measurable object, and their limits pushed the field toward attribution graphs and readouts in language. The thread of this note is the gap between a direction that can be labeled and a computation that can be shown.

Interpretability research can now name millions of features inside a production language model. Scaling Monosemanticity extracted about 34 million features from Claude 3 Sonnet, and clamping just one of them to a high value was enough to steer nearly every answer toward the topic of that feature. Yet a named feature, on its own, is not evidence that the model uses it to produce an answer. When Anthropic later traced how Claude 3.5 Haiku actually adds 36 + 59, the computation ran through two parallel paths, but when the model was asked how it got 95, it described the textbook carry method instead.

This note has four parts. The first part tells the history as the question that each step answered and the question that it left open. The second part describes what an SAE is today, down to the tensors, the sparsity mechanisms and the training loop in SAELens. The third part covers the methods that put features back into a computation: attribution graphs, crosscoders, natural-language autoencoders, the workspace paper and the J++ lens. The last part lists the questions that the field has not answered yet. All results come from the papers listed at the end, and the code excerpts come from SAELens and TransformerLens.

Circuits: the residual stream as a shared channel

A Mathematical Framework for Transformer Circuits starts from a fact about the architecture. Every transformer block adds its output to a residual stream, and every later block reads from the same sum. So the whole model can be rewritten as a sum of paths: the embedding directly to the output, the embedding through one attention head, the embedding through two heads in sequence, and so on.

flowchart TD
    E["token embedding"] --> R1(("residual stream"))
    R1 --> H1["layer 1 heads"]
    H1 -- "add output" --> R2(("residual stream"))
    R1 --> R2
    R2 --> H2["layer 2 heads"]
    H2 -- "add output" --> R3(("residual stream"))
    R2 --> R3
    R3 --> U["next-token logits"]

Figure 2: Blocks read from and add to one shared stream, so the model’s output is a sum over paths through the blocks.

Each attention head then splits into two parts. The QK circuit, WQ⊤WKW_Q^\top W_KWQ⊤​WK​, decides which earlier positions a token attends to, and the OV circuit, WOWVW_O W_VWO​WV​, decides what is copied from there into the stream. A “circuit” is a path through such matrices that implements a behavior. Two conventions from this paper still hold: the residual stream is a communication channel that every layer reads and writes, and the natural unit is a direction in this stream, not a neuron. The paper worked out attention-only models with zero, one and two layers exactly, but it did not say how to find circuits in a model with 70 layers.

In-context Learning and Induction Heads supplied the first convincing circuit. An induction head looks for the previous occurrence of the current token and copies the token that followed it. It needs a partner: a previous-token head writes “the token before me” into the stream, and the induction head uses this information to find the match. The paper supported this mechanism with six independent lines of evidence. Among them are a phase change in training, in which induction heads appear exactly when in-context learning improves, and ablations that remove the heads and the ability together. Mechanism, intervention and an account of how the circuit forms during training became the template for later work.

Superposition: why neurons aren’t the right unit

Toy Models of Superposition explained why reading individual neurons fails. The toy model compresses nnn features into m<nm<nm<n hidden dimensions and then maps them back, with a ReLU at the output. When the features are dense, the model keeps only the most important ones, each in its own dimension, and drops the rest. Once the features are sparse enough, the model packs extra features into shared, non-orthogonal directions, because two features that are rarely active seldom collide. The packed features settle into regular shapes, such as antipodal pairs, triangles and pentagons, depending on how often each feature is active and how much it matters.

Figure 3: Five features in two dimensions. Dense features get their own axes and the rest are dropped; sparse features share the space at the corners of a pentagon.

Once superposition is real, “find the neuron for X” is no longer the right question. A better question is “find a sparse set of directions whose combination reconstructs the activation”. This is a dictionary-learning problem, and exactly the problem that an SAE solves.

Dictionaries: making “feature” measurable

Towards Monosemanticity ran the first serious SAE on a language model: a one-layer transformer with an MLP of 512 neurons, and dictionaries from 512 up to 131,072 latents. The main analysis used 4,096 latents, eight times overcomplete. The learned latents were often interpretable, and wider dictionaries split features into finer ones. The paper also set up evaluation habits that are still in use: activation examples, logit effects and ablations.

Scaling Monosemanticity applied the same instrument to Claude 3 Sonnet, with dictionaries of 1, 4 and 34 million features. The features were multilingual, some responded to images as well as to text, some were relevant to safety, and clamping them changed the behavior of the model in a coherent way.

These results also set up the current debate. A feature that fires whenever a particular topic comes up is interpretable. Whether the model actually uses this feature when it answers a question about that topic is a separate claim, and steering experiments are the start of this evidence, not the end.

Graphs and language: putting features back into the computation

A dictionary shows which directions exist, but not which of them were used, and in what order, to produce a given token. On the Biology of a Large Language Model is the bridge back to circuits. It builds a replacement model for Claude 3.5 Haiku, traces individual outputs through this replacement, and finds computations that the text of the model itself does not mention. The section on Attribution graphs below describes the method.

The latest work approaches the same gap from the output side: if features are hard to name, can the activations of the model be explained in language, either by the model itself or by a trained translator? This question is the second half of the frontier in this post.

What an SAE is today

The object

An SAE is an autoencoder whose hidden layer is much wider than its input. For an activation x∈Rdinx\in\mathbb{R}^{d_{\text{in}}}x∈Rdin​:

z=act⁡(Wex+be),x^=Wdz+bd,z=\operatorname{act}(W_e x+b_e),\qquad \hat{x}=W_d z+b_d,z=act(We​x+be​),x^=Wd​z+bd​,

with We∈Rdsae×dinW_e\in\mathbb{R}^{d_{\text{sae}}\times d_{\text{in}}}We​∈Rdsae​×din​, Wd∈Rdin×dsaeW_d\in\mathbb{R}^{d_{\text{in}}\times d_{\text{sae}}}Wd​∈Rdin​×dsae​ and dsae≫dind_{\text{sae}}\gg d_{\text{in}}dsae​≫din​. Training minimizes the reconstruction error plus a sparsity cost:

L=∥x−x^∥22+λ S(z).\mathcal{L}=\lVert x-\hat{x}\rVert_2^2+\lambda\,S(z).L=∥x−x^∥22​+λS(z).

The interesting part is SSS. With the L1 norm, the model pays per unit of activation, so the active coefficients are shrunk toward zero. With a count of active latents, the model pays per latent, and the coefficients themselves are not penalized. With a learned threshold, the line between active and inactive becomes a parameter. I derived these objectives on a toy problem in an earlier post, and the short version is that L1 shrinks, TopK truncates and JumpReLU thresholds.

Two details matter in code.

TopK limits the count; it does not fix the count. SAELens selects the kkk largest pre-activations, applies ReLU to them and scatters them back (shortened from the source):

topk_values, topk_indices = torch.topk(x, k=self.k, dim=-1, sorted=False)
values = topk_values.relu()
result = torch.zeros_like(x)
result.scatter_(-1, topk_indices, values)

A token with fewer than kkk positive pre-activations therefore ends up with fewer than kkk active latents. BatchTopK relaxes the limit further: it chooses the top k×k\timesk×batch activations across a whole batch, so that easy tokens use fewer latents and hard tokens use more.

JumpReLU needs a gradient for its threshold. The forward pass is a step function, whose gradient is zero almost everywhere. The JumpReLU paper replaces this gradient with a rectangle kernel KKK of width www (the bandwidth) around the threshold. For the activation z=u⋅1[u>θ]z=u\cdot\mathbf{1}[u>\theta]z=u⋅1[u>θ] and for the L0 penalty 1[u>θ]\mathbf{1}[u>\theta]1[u>θ], the pseudo-derivatives with respect to θ\thetaθ are

∂z∂θ≈−θw K ⁣(u−θw),∂ 1[u>θ]∂θ≈−1w K ⁣(u−θw),\frac{\partial z}{\partial \theta}\approx-\frac{\theta}{w}\,K\!\left(\frac{u-\theta}{w}\right),\qquad \frac{\partial\,\mathbf{1}[u>\theta]}{\partial \theta}\approx-\frac{1}{w}\,K\!\left(\frac{u-\theta}{w}\right),∂θ∂z​≈−wθ​K(wu−θ​),∂θ∂1[u>θ]​≈−w1​K(wu−θ​),

while the gradient of the input passes straight through wherever the gate is open. SAELens implements both as custom torch.autograd.Function classes, JumpReLU and Step, with exactly these factors.

The training loop

flowchart TD
    A["corpus"] --> B["model forward pass"]
    B --> C["hooked activation x"]
    C --> D["normalize and batch"]
    D --> E["encoder: W_e x + b_e"]
    E --> F["sparsity gate"]
    F --> G["latents z"]
    G --> H["decoder: W_d z + b_d"]
    H --> I["loss: reconstruction + sparsity"]
    I --> K["optimizer step and dead-latent fixes"]
    K -.-> E

Figure 5: One SAE training run; the dotted arrow is the next batch. The gate is L1, TopK or JumpReLU; evaluation (CE loss recovered, L0, auto-interpretability) runs on the trained dictionary.

A modern training run combines five loops. None of them is mathematically deep, but all of them change the result.

  1. Collect activations. A hook captures the residual stream, an MLP output or an attention output over a large corpus, and the activations are cached and shuffled. Normalization matters: if the norms of the activations drift between batches, the SAE can learn a dictionary that depends on the norm. SAELens offers none, expected_average_only_in, constant_norm_rescale, layer_norm and covariance_whitening.

  2. Initialize. The decoder columns are scaled to a fixed norm (decoder_init_norm, 0.1 by default), the encoder starts as the transpose of the decoder, and the decoder bias starts at zero. Without a fixed decoder norm, the optimizer can lower the L1 penalty without changing the output, by shrinking the latents and growing the decoder columns.

  3. Optimize. Adam with warmup and decay, with batches counted in tokens, because each token yields one activation vector. The GPT-4 SAE in the TopK paper saw 40 billion tokens.

  4. Keep latents alive. A latent is “dead” if it has not fired for a window of steps. Dead latents waste capacity and distort the sparsity statistics. SAELens tracks them with a counter:

    def dead_neurons(self) -> torch.Tensor:
    return (self.n_forward_passes_since_fired > self.cfg.dead_feature_window).bool()

    Three fixes are in use. AuxK, from the TopK paper, adds a loss that lets the top dead latents reconstruct the residual error, so that these latents receive gradient. A pre-activation loss, from Anthropic’s JumpReLU recipe, pushes dead latents back toward their threshold. Resampling reinitializes dead latents toward inputs that are poorly reconstructed, and it is common in older L1 recipes.

  5. Evaluate. Reconstruction alone is not enough: in the experiment of the earlier post, a larger budget of active latents reconstructed better while it recovered fewer of the true directions. The usual set of metrics contains:

    • CE loss recovered: insert the reconstruction into the model and measure how much of the next-token loss remains;
    • L0 and the fraction of dead latents;
    • auto-interpretability: a model names a feature from its examples, and the name is scored;
    • sparse probing and causal interventions.

    SAEBench combines these metrics across hundreds of public SAEs, because most papers had optimized one proxy at a time.

The hook

TransformerLens supplies the connections. A HookPoint is an identity module at a named site:

def forward(self, x: Tensor) -> Tensor:
    return x

A hook function registered at this site can cache the activation for training, or it can return a replacement at inference, such as the reconstruction of an SAE. The method HookedSAETransformer.add_sae(sae) in SAELens connects an SAE to its hook name and can keep the reconstruction error as a separate term, so that the output of the model stays unchanged even though the SAE is imperfect.

The hook name is part of the interpretation. blocks.5.hook_resid_pre and blocks.5.hook_attn_out have the same shape but are different objects: the first is the stream entering the block, and the second is what attention adds to it. A dictionary trained at one site does not transfer to another site just because the shapes match.

Putting features back into the computation

The methods below try to answer the questions that a dictionary cannot answer: which features take part in this computation, in what order, and whether the account of the model itself matches the computation.

Attribution graphs

On the Biology of a Large Language Model traces outputs of Claude 3.5 Haiku through a replacement model with three parts:

  1. A cross-layer transcoder replaces the MLPs. It has about 30 million features, and each feature reads from the residual stream at one layer and writes to the MLP outputs of that layer and later layers. A transcoder models the function of the MLP, from input to output, instead of only reconstructing an activation, and circuit work needs exactly this property.
  2. Attention stays as it is. For a given prompt, the attention patterns and the normalization denominators of the original model are frozen. The replacement still applies a JumpReLU to each feature, so it is not a linear model. What becomes linear is the direct effect of one feature’s activation on the pre-activation of a later feature, through the residual stream and the frozen attention.
  3. Error nodes hold what the replacement misses at each position, so the trace shows where it is incomplete.
flowchart TD
    T["prompt tokens"] --> F1["transcoder features, early layers"]
    F1 -- "frozen attention moves information between positions" --> F2["transcoder features, later layers"]
    F2 --> O["output logit for the target token"]

Figure 6: An attribution graph. With attention and normalization frozen, the direct effects between active features can be traced backward exactly. Error nodes, not drawn, sit beside the features and hold what the replacement misses.

Because these direct effects are linear once attention and normalization are frozen, the direct influence of every active feature on later features and on a target logit can be computed exactly for this prompt. The result is a graph from the input tokens through the features to the output. The case studies show structure that the text does not show:

  • Poems: the model chooses the rhyming word before it writes the line that ends with this word.
  • Hallucination: features for “cannot answer” are on by default, and features for known entities switch them off. A hallucination happens when a familiar name switches these features off although the model does not know the answer.
  • Addition: the model computes the rough size of the sum and its last digit along separate paths and combines them, but it describes the carry method when asked.

The limits are equally concrete. The replacement is an approximation, and its error nodes cannot be interpreted. A graph explains one output, not the model. In addition, the method needs a trained transcoder and one attribution pass per prompt.

Crosscoders

A crosscoder reads and writes several layers, or several models, with one dictionary. If superposition spreads a feature across layers, a dictionary for a single layer only sees a slice of the feature, while a crosscoder can follow the feature as it persists through the stream, or find which features fine-tuning added or removed. The note from 2024 is explicitly preliminary, so it describes a direction rather than a finished method.

Language as the readout

Three recent results turn interpretation into translation.

Introspection. Emergent Introspective Awareness injects a concept directly into the activations of a model and asks whether the model notices anything. Models sometimes report the injected concept and sometimes adjust an internal state on request, but they do so unreliably and depending on the task.

Natural language autoencoders. An activation verbalizer turns an activation into text, and an activation reconstructor turns the text back into an activation. Both start from the target model and are trained jointly with reinforcement learning: the verbalizer receives a reward when its text lets the reconstructor recover the activation.

flowchart TD
    A["activation from the target model"] --> V["activation verbalizer (an LLM)"]
    V --> T["explanation in plain text"]
    T --> R["activation reconstructor (an LLM)"]
    R --> A2["reconstructed activation"]
    A2 --> L["error against the original activation"]
    L -. "RL reward" .-> V

Figure 7: A natural language autoencoder. Language is the bottleneck, so the code is readable by construction.

No supervision forces the explanations to be interpretable, but they become more informative as the reconstruction improves. In a pre-deployment audit of Claude Opus 4.6, NLAs revealed evaluation awareness that the model never expressed in words, and agents equipped with NLAs performed better than the baselines on an automated auditing benchmark. The paper states the limits openly: explanations can invent specific details, the verbalizer can infer more than the activation contains, and training requires reinforcement learning on two full LLMs.

The workspace paper. Verbalizable Representations Form a Global Workspace introduces the Jacobian lens (J-lens). The J-lens finds the representations that a model is about to put into words, and the paper argues that these representations form a workspace. This “J-space” lies in a middle band of layers and has limited capacity, so most features lie outside it. It supports verbal report, directed modulation and multi-step reasoning: ablating its top directions damages multi-hop reasoning, while tasks such as classification stay largely intact. In auditing, strategic content appeared there even when it was absent from the outputs. In addition, the paper trained a model to state its principles when it is interrupted (counterfactual reflection training). This training improved its behavior without interruption, and the gain largely disappeared when the implanted representations were ablated.

The J++ lens

The J-lens reads out intermediate concepts with one linear map per layer, built by averaging Jacobians over many token positions. The J++ lens, from the circuits update of October 2026, clusters the activations of each layer and fits one Jacobian per cluster. It combines the clusters with learned weights that mostly discard poor clusters, uses layerwise relevance propagation from the R-lens, and filters spurious tokens. It is still one linear map per layer and can directly replace the earlier lenses, and it reveals intermediate variables more reliably than either earlier lens. The update presents the method as preliminary.

What’s still open

Five problems remain open, and a bigger dictionary solves none of them.

  1. Feature absorption. A specific feature can be absorbed into a more general feature, so the SAE reconstructs well without a dedicated latent for the specific concept, and the dictionary looks complete although it is not. One response is Matryoshka SAEs: they train nested dictionaries of increasing size together.
  2. Evaluation. Reconstruction, L0, dead latents, auto-interpretability and causal effect measure different things and trade off against each other. A method can improve one metric and worsen another, and a paper that focuses on one metric may not report the others.
  3. Faithfulness. An attribution graph is a hypothesis about a computation, and a natural-language explanation is a hypothesis about a representation. Neither is guaranteed to match the mechanism, and the addition case shows that the account of a model itself can differ from its computation.
  4. Scale. A dictionary with 34 million features is already large, and a graph over every layer of a production model is even larger. The cost of interpretation now limits how often it can be done.
  5. Necessity. If graphs can trace a circuit through transcoders and NLAs can explain an activation without a dictionary, what is the role of the SAE? My own answer is that the SAE is a labeling layer: it gives nodes names and a shared vocabulary. This role is valuable, but it is not the same as being the explanation.

Conclusion

The field began by decomposing weights into circuits, then found that neurons are not the right unit, built dictionaries of directions, and finally discovered that a dictionary is not a computation. The newest work is the return trip: it puts features back into a graph, or translates activations into language, and checks that the behavior of the model follows.

Naming a feature is a measurement; showing that the model uses the feature requires an intervention, a graph or a causal test, and the SAE made only the first of these easy.
