解码注意力的 INT8 KV 缓存：量化误差、线程束映射与延迟

键和值各有 64 个通道时，逐向量 INT8 量化把每对 KV 从 256 字节压到 136 字节；在 RTX 5070 Laptop 上固定线程分工后，两组解码测试却分别是 FP16 快约 1.70 和 1.43 倍。另用 CPU 对照不同 4 位编码，检验键的点积误差和值的重建误差怎样影响注意力输出。

自回归解码每生成一个 token，就要用当前查询重新读取可见历史。历史位置的 key 可以直接拿来做点积，value 则用于随后的加权求和。两者都能复用已经算好的值，但上下文越长、同时服务的序列越多，需要保留和访问的 KV 也就越多。

将 K/V 从浮点压成整数可以直接减少容量，能否缩短解码耗时还取决于反量化的开销、相邻线程发出的读取请求以及归约的分工。压缩也可能改变结果。同一个量化误差，沿查询方向的分量会改变内积，正交分量却不会，因此还要看误差如何传到注意力输出。

GPU 上有两个条件需要分开。让两个实现读取同一份 INT8 缓存，比较的是线程怎样分工；让同一套 split 分工分别读取 INT8 和 FP16，比较的才是更换存储格式对完整调用的影响。在后一个对照中，两种形状都是容量更大的 FP16 更快。 至于量化引入的输出误差，我在 CPU 上对同一批输入比较逐行 absmax、随机旋转配球面码本，以及带 QJL 残差的编码。这些 4 位编码没有参加 GPU 计时。

解码注意力对历史键和值的读取

设当前查询为 q∈Rdq\in\mathbb R^dq∈Rd，共有 NNN 个可见 token，每个 token 保留一对各有 ddd 个分量的键和值。同一个查询先与这些键做点积，得出的权重再用于值向量的加权求和。

zt=1d∑j=0d−1qjkt,j,pt=exp⁡(zt−m)∑uexp⁡(zu−m),oj=∑t=0N−1ptvt,j,z_t=\frac{1}{\sqrt d}\sum_{j=0}^{d-1}q_jk_{t,j},\qquad p_t=\frac{\exp(z_t-m)}{\sum_u\exp(z_u-m)},\qquad o_j=\sum_{t=0}^{N-1}p_tv_{t,j},zt​=d​1​j=0∑d−1​qj​kt,j​,pt​=∑u​exp(zu​−m)exp(zt​−m)​,oj​=t=0∑N−1​pt​vt,j​,

其中 m=max⁡tztm=\max_tz_tm=maxt​zt​。所有分数减去同一个最大值，Softmax 的各项比例保持不变，也避开了对很大正数直接取指数的溢出风险。计算键的点积要沿通道求和，计算值的加权和则要遍历历史 token；两个方向的内存布局不同，适合的线程分工也就不同。

缓存保存的是 kt,vtk_t,v_tkt​,vt​。下一轮解码会换一个查询，所需的权重 ptp_tpt​ 必须重新计算。这里假定调用者已经筛出有效历史，接口不处理掩码、GQA 的头映射、分页寻址或缓存追加。有 HHH 个注意力头时，K/V 按 [H,N,d] 连续排列，同一向量的各通道在内存中相邻。

带逐向量缩放因子的 INT8 键值缓存大小

同一个 token 的 K 向量和 V 向量各用一个独立的缩放因子。对向量 xxx，编码按下面的规则进行。

s=max⁡j∣xj∣127,cj=clip⁡(round⁡even(xj/s),−127,127),x^j=scj.s=\frac{\max_j|x_j|}{127},\qquad c_j=\operatorname{clip}\left(\operatorname{round}_{\rm even}(x_j/s),-127,127\right), \qquad \widehat x_j=sc_j.s=127maxj​∣xj​∣​,cj​=clip(roundeven​(xj​/s),−127,127),xj​=scj​.

编码采用最近偶数舍入，整数范围排除 −128-128−128，零向量用零尺度和全零整数表示。解码时读出有符号字节，转成浮点并乘回尺度。由于尺度也会舍入到 FP32，数值参考须读取缓存中实际保存的尺度，否则测到的误差还包含参考实现自己改变输入带来的差异。

图中的尺度字段放大了表示：d=64d=64d=64 时，一对 FP16 K/V 占 256 字节，INT8 数据占 128 字节，再加两个 FP32 尺度，共 136 字节。推广到 HHH 个 head、NNN 个 token：

BFP16=4HNd,BINT8=2HNd+8HN.B_{\rm FP16}=4HNd,\qquad B_{\rm INT8}=2HNd+8HN.BFP16​=4HNd,BINT8​=2HNd+8HN.

于是在 d=64d=64d=64 时这份 INT8 格式实际是每个标量 8.5 bit，容量为原来的 136/256136/256136/256，约 1.882 倍压缩。一般维度下每个标量的预算为 8+32/d8+32/d8+32/d bit。这只计算 K/V 与尺度；权重、Q、输出和临时工作区另占空间。

实现分成 QK、Softmax、PV 三个 kernel。中间分数写进 FP32 工作区 S[H,N]，Softmax 原地把它改成概率，PV 再读概率。这多花 4HN4HN4HN 字节，换来的是两个归约能分开观察。下面称为 simple 和 split 的两条路径都是这个结构，三步没有融成一个 kernel。

QK 点积的每 token 单线程映射

第一种 QK 映射给每个 token 分配一个线程。它固定当前查询向量（query），沿该 token 的键向量（key）逐项读取 ddd 个通道，在同一线程里完成点积。对应的内循环如下，变量名沿用源码。逐 token 的 QK 源码

float sum = 0.0f;
for (int i = 0; i < head_dim; i++) {
    float K = k_scale[row * seq_len + col]
        * static_cast<float>(
            K_int8[(row * seq_len + col) * head_dim + i]);
    sum += Q[row * head_dim + i] * K;
}
S[row * seq_len + col] = sum / sqrtf(float(head_dim));

row 表示注意力头，col 表示历史 token。单个线程从头到尾读取一个键向量，其地址连续；但内存系统合并的是同一条指令中整个 warp 的地址。block(16,16) 让一个 warp 分成两组，每组 16 个 lane 处理同一注意力头的相邻 token。当循环变量 i 相同时，这些线程读取不同 token 的同一通道，相邻地址相差 head_dim 字节。若 d=64d=64d=64，相邻线程各取一个字节，地址相差 64 字节，落在编号相差 2 的 32 字节扇区，中间跳过了一个完整扇区。

QK 点积的每 token 单线程束映射

第二种实现让整个 warp 合作处理一个 token。lane 0 计算通道 0、32、64 等位置的乘积，lane 1 计算 1、33、65 等位置的乘积。d=64d=64d=64 时每个 lane 只算两个乘积，同一轮 32 个 lane 正好覆盖一段连续的 32 字节，再用 warp shuffle 汇总。

对给定注意力头中的一个 token，同一键向量的全部通道共用一个量化尺度。因此可先沿通道对乘积求和，最后乘一次这个尺度。

q⊤(stct)=st∑jqjct,j.q^\top(s_tc_t)=s_t\sum_jq_jc_{t,j}.q⊤(st​ct​)=st​j∑​qj​ct,j​.

把乘尺度挪到求和之后，就是下面这段求点积的代码。warp 协作的 QK 源码

const int8_t* k_row = K_int8 + (head * seq_len + token) * head_dim;
float sum = 0.0f;
for (int d = lane; d < head_dim; d += WARP_SIZE) {
    sum = fmaf(q_smem[d], static_cast<float>(k_row[d]), sum);
}
sum = warp_sum(sum);
if (lane == 0) {
    S[head * seq_len + token] =
        sum * k_scale[head * seq_len + token] * inv_sqrt_dim;
}

一个线程块包含 8 个 warp，共同负责一个注意力头的 8 个 token。各线程把查询协作载入 q_smem，通过块级屏障后，8 个内积就能共用它。warp_sum 以 16、8、4、2、1 为步长交换并累加各 lane 的部分和。实现把无效 token 的判断放在查询加载和块级同步之后；同一 warp 内的 token 相同，所以处理尾块时会整组退出。

这项改动也带来代价：一个短内积现在占满 32 个线程、做五级归约，FP32 的加法顺序和尺度相乘的位置都变了。实数代数保证两种写法等价，不保证浮点结果逐位一致，也不保证短输入一定更快。

PV 沿 token 轴的加权归约

QK 固定 token 后沿通道归约，PV 则固定输出通道后沿历史 token 归约。这里每个线程负责一个通道，按下式遍历全部 token。

oj=∑t(ptstV)ct,jV.o_j=\sum_t (p_ts^V_t)c^V_{t,j}.oj​=t∑​(pt​stV​)ct,jV​.

括号里的权重与输出通道无关，可以共享。split 每轮先把 256 个 probability * v_scale 放进共享内存，各输出通道再复用；simple 让每个输出线程自己去读概率和尺度。最后一个 tile 不满 256 个 token 时只遍历有效长度；没有输出通道的线程照样参加 block 同步，免得下一轮把别人还在使用的权重覆盖掉。两版都要读完全部 key、合并全部 value，差别只在任务如何划分、一次读取能被几个输出共用。

固定线程映射比较 INT8 与 FP16 的解码耗时

若只比较两个读 INT8 的实现，测到的是分工变化。为估计缓存格式对整个调用的影响，split FP16 沿用 split INT8 的工作划分。QK 用一个 warp 算一个 token，一个 block 放八个 warp。三段都共用 FP32 的分数工作区和同一 softmax，PV 仍以 256 个 token 为一块。Q、分数、累加器和输出都是 FP32。唯一换掉的表示是 K/V：改读 half 之后，原来的整数转换和尺度读取也跟着改变。这样可以问存储格式的总影响，无法单独给一条转换指令定价。

三个入口都在计时前选定，split 不再逐次查询设备属性。调用者传入 stream、工作区和输出。Q 和输出偏移一个 float，INT8 的 K/V 偏移一个字节，FP16 的 K/V 偏移一个 half。各格式都从一个元素的合法偏移开始读，实际偏移的字节数随元素宽度变化。编码、分配与传输排除在计时外。每种格式都有两份 CPU FP64 参考，一份读实际保存的值，一份读原始 FP32 输入。以 H=8,N=4096,d=64H=8,N=4096,d=64H=8,N=4096,d=64 普通输入为例，单是表示造成的输出 RMSE，INT8 为 3.9040×10−53.9040\times10^{-5}3.9040×10−5，FP16 为 1.7893×10−61.7893\times10^{-6}1.7893×10−6。两个数都是这组合成输入的表示误差。

INT8 解量化后的 FP32 乘加指令

INT8 缓存节省的是存储字节，点积仍要在读出以后转换到浮点。被测二进制中 simple 的 QK 内层 PTX 如下，省略了行号注释。

ld.global.s8 %rs1, [%rd17+-3];
cvt.rn.f32.s16 %r46, %rs1;
mul.f32 %r47, %r3, %r46;
ld.global.b32 %r48, [%rd43+-16];
fma.rn.f32 %r49, %r48, %r47, %r127;

ld.global.s8 从显存读一个有符号字节，后续指令把它转成 FP32、乘回尺度，再与查询做融合乘加（FMA）。s16 表示转换发生前的寄存器类型，显存里的元素仍只占一个字节。split 还要用五级 shuffle 做 warp 内归约。这份二进制中可以找到普通加载和 FFMA，未见 HMMA、IMMA 或 MMA 指令，因此 INT8 改变的是缓存表示，点积仍走浮点计算路径。

量化表示误差与注意力实现误差

前面的两种 INT8 内核读的是同一份量化数据，因此即使它们彼此吻合，也只能检验 CUDA 如何计算这个已经压缩的输入。要量出缓存格式本身引入的误差，还须把输出与未量化的 K/V 作比较。

对同一组查询，用 PPP 表示原始键产生的权重，用 OOO 表示它对原始值求得的加权输出。将键替换为重建值后，新的权重记为 P^\widehat PP。

P=softmax⁡(QK⊤/d),O=PV,P^=softmax⁡(QK^⊤/d).P=\operatorname{softmax}(QK^\top/\sqrt d),\quad O=PV, \qquad \widehat P=\operatorname{softmax}(Q\widehat K^\top/\sqrt d).P=softmax(QK⊤/d​),O=PV,P=softmax(QK⊤/d​).

键误差是否影响权重，取决于它在查询方向上的投影。同样长度的 Δk\Delta kΔk 若平行于查询，点积会改变；若与查询垂直，点积就保持不变。因此只凭 K 的重建均方误差无法预测注意力输出。V 的误差则在权重确定后直接进入加权和。

图 4　左路的键误差先改变与 query 的点积，进而改写整行权重；右路的值误差直接进入最后的加权和。

令 ΔV=V^−V\Delta V=\widehat V-VΔV=V−V，有精确分解

O^−O=(P^−P)V+PΔV+(P^−P)ΔV.\widehat O-O=(\widehat P-P)V+P\Delta V+(\widehat P-P)\Delta V.O−O=(P−P)V+PΔV+(P−P)ΔV.

前两项分别是只量化 K、只量化 V，最后一项是联合量化的交互。因此 K-only 与 V-only 的误差数值不能直接相加，取 RMSE 之后还会冒出误差向量之间的交叉项。

CUDA 检查保存三份答案：原始 FP32 K/V 提到 CPU binary64 算出的 ooriginalo_{\rm original}ooriginal​，实际 INT8 加 FP32 尺度解码后用 binary64 算出的 odecodedo_{\rm decoded}odecoded​，以及 GPU 输出 oGPUo_{\rm GPU}oGPU​。它们满足

oGPU−ooriginal=(oGPU−odecoded)+(odecoded−ooriginal).o_{\rm GPU}-o_{\rm original} =(o_{\rm GPU}-o_{\rm decoded})+(o_{\rm decoded}-o_{\rm original}).oGPU​−ooriginal​=(oGPU​−odecoded​)+(odecoded​−ooriginal​).

第一个差值衡量 CUDA 相对同一份已解码输入的偏差，第二个差值则衡量改变缓存表示本身的影响。即使 kernel 完全符合解码后的数值参考，量化也可能已经改变任务输出，因此需要为两种误差分别保留对照。

随机旋转与 4 位码本量化

逐行 absmax 用最大坐标决定整行的量化间隔，因此一个离群值就可能降低其余坐标的精度。TurboQuant 的 4 bit MSE 路径先对方向做随机旋转，使各坐标的分布更接近，再据此设计公共码本，将更多重建值分给高概率区域。TurboQuant 原论文

对于非零向量 x=rux=rux=ru，长度为 r=∥x∥2r=\|x\|_2r=∥x∥2​。编码器单独保存 rrr，只对满足 ∥u∥2=1\|u\|_2=1∥u∥2​=1 的方向向量作低位宽量化。随机正交矩阵 RRR 把它映射为 z=Ruz=Ruz=Ru，长度保持不变。在量化之前，乘以 R⊤R^\topR⊤ 就能恢复原方向。随机旋转的作用是使一个固定方向在球面上均匀取向；精度损失发生在随后的量化。

对均匀球面方向，单个坐标 ttt 的密度是

fd(t)=Γ(d/2)π Γ((d−1)/2)(1−t2)(d−3)/2,−1<t<1.f_d(t)=\frac{\Gamma(d/2)}{\sqrt\pi\,\Gamma((d-1)/2)} (1-t^2)^{(d-3)/2},\qquad -1<t<1.fd​(t)=π​Γ((d−1)/2)Γ(d/2)​(1−t2)(d−3)/2,−1<t<1.

不需要假设所有坐标完全独立才能这样设计。它们的平方和固定为 1，而总重建平方误差是逐坐标平方误差之和，期望能一项项加起来。把码本映射记作 CbC_bCb​，重建是

CPU 实现先对高斯矩阵做 QR 分解，再按三角因子对角元的符号翻转正交因子的列，得到 Haar 正交矩阵；码本由有限维球面密度积分求出。每行长度仍存 FP32，所以实验里包含长度存储的舍入误差。旋转与码本由多个向量共享，这部分存储得按共享范围另外摊销。

随机旋转让一个很大的坐标分散到多个通道，有机会减轻逐行 absmax 受离群值支配的问题。但对原本稀疏的向量，它也会把精确零变成一般非零值。因此比较低位宽编码时，除了观察最大坐标，还要实际比较重建后的注意力输出。

KV 压缩的存储量、解码耗时与输出误差

d=64d=64d=64 时，每对 K/V 从 FP16 的 256 字节压缩到含尺度的 INT8 格式，只需 136 字节。让 warp 沿通道读也降低了所测形状下 QK 的读取扇区数。然而，这两项变化并不能直接预测整次解码的耗时：两种线程映射的优劣随形状改变，而在同一套 split 分工下，测到的两个形状都是 FP16 更快。

对输出精度也要沿实际计算判断。K 的误差经查询点积和 softmax 改变权重，V 的误差则进入加权和值。在这组输入上，随机旋转帮助球面码本处理离群或稀疏向量，能精确表示零的其他编码仍可能有更小误差。QJL 可使固定查询的内积估计无偏，但经过非线性的 softmax 后，概率均值和输出 RMSE 并没有同样的保证。
