从 Volta 到 Blackwell：Tensor Core 的矩阵指令与数据搬运

Volta 上，一个线程束协作完成半精度矩阵乘加。到 Hopper，四个线程束可以共同提交矩阵指令，专门的搬运单元则提前准备下一块输入。B200 又把累加结果移入专用张量内存，即使同属 Blackwell，消费级 RTX 5070 Laptop 也沿用另一套指令。

看一张显卡的矩阵算力，得先确认它用什么精度、有没有利用稀疏性，以及这个数对应几张卡。单卡算稠密 FP8，和八张卡一起算稀疏 FP8，即使单位都写成 FLOPS，也不能直接相除。落实到一个具体核函数，还要看哪些线程能发出矩阵指令、它们怎样取到操作数，以及一块矩阵还没算完时部分和存在哪里。

物理 Tensor Core 与 warp 矩阵指令的运算粒度

张量核心（Tensor Core）执行小矩阵乘加 D=AB+CD=AB+CD=AB+C。AAA 和 BBB 可以用较窄的格式，累加器用较宽格式，以减少长点积的数值损失。一次 M×N×KM\times N\times KM×N×K 矩阵乘加有 MNKMNKMNK 个乘加（FMA），也就有 2MNK2MNK2MNK 个 FLOP。物理单元一次做多大的乘法，与一个线程束（warp）看到的矩阵指令形状，是两个尺度。对 Volta，一个单元的一次 4×4×44\times4\times44×4×4 运算含 64 个 FMA，warp 层看到的 HMMA 指令可以覆盖 8×8×48\times8\times48×8×4。

核算一张卡的峰值，要知道每个物理单元一拍能做多少次乘加。给 CUDA 线程分工时，则要看指令要求哪些线程一起执行，以及它们到哪里取各自的操作数。这也是比较后面几代芯片时要用到的两个尺度。

Volta 的 FP16 混合精度与 Turing 的整数乘加

V100 SXM2 有 80 个 SM，每个 SM 配 8 个 Tensor Core。按照 1.53 GHz 的 boost 时钟计算，80×8×64×2×1.5380\times8\times64\times2\times1.5380×8×64×2×1.53 给出的峰值约为 125 TFLOPS，对应 FP16 输入、FP32 累加，同卡的 FP32 标量峰值则是 15.7 TFLOPS。要让矩阵单元持续工作，寄存器和共享内存得及时供给操作数，矩阵太窄还可能填不满计算块。Volta 要用普通加载指令把数据从全局内存搬入共享内存，并用屏障等这批数据就绪，访存和计算也就需要共用指令发射资源。

乘法输入采用 FP16，并不能直接确定内部乘积保留多少位。PTX 对 Volta 这条 WMMA 路径规定，FP16 输入的乘法精度至少为单精度；当 C、D 都取 FP16 时，又允许按 FP16 累加。前面约 125 TFLOPS 指的是这里讨论的混合精度配置。640 个单元分布在 80 个 SM 上，一个 SM 每拍能做 8×64×2=1,0248\times64\times2=1{,}0248×64×2=1,024 个 Tensor FLOP，64 个 FP32 核按每拍各做一个 FMA 则是 128 FLOP。PTX 对 WMMA 操作数和乘加精度的定义

Turing 给第二代单元加上 INT8 和 INT4，累加使用 INT32。70 W 的 T4 标 65 TFLOPS 混合精度、130 TOPS INT8、260 TOPS INT4。权重位宽减半也能减少推理时读取的字节，但使用何种量化尺度、模型能容忍多大误差，还需要在软件端决定。RTX 20 系列把这条矩阵计算路径带到了消费卡。

Ampere 的 TF32、BF16 与 2:4 结构化稀疏

到了 Ampere，A100 仍由一个 warp 协作执行 mma.m16n8k16 这样的矩阵指令，但同一套单元已支持更多输入类型和结构化稀疏。108 个 SM 各有 4 个 Tensor Core，每个单元每周期可做 256 个 FP16 FMA，按 1.41 GHz 计算，稠密 FP16/BF16 峰值约为 312 TFLOPS。改用下面其他格式，所能达到的峰值也会改变。

  • TF32 的指数为 8 位，小数部分为 10 位。FP32 输入在进入乘法前舍入，累加保留 FP32。A100 的稠密 TF32 峰值为 156 TFLOPS。
  • BF16 也用 8 位指数，小数部分只有 7 位，配 FP32 累加。A100 的稠密峰值为 312 TFLOPS；FP64 Tensor Core 则为 19.5 TFLOPS。
  • 2:4 结构化稀疏要求沿归约维 KKK 的每组四个位置满足指定稀疏结构，元数据指出保留的两个位置。符合条件时，换算成等效稠密工作量的 BF16 峰值为 624 TFLOPS。模型剪枝后能保住多少精度要另行验证。

这些数值格式之外，Ampere 还加入 cp.async。它可以直接把数据从全局内存异步复制到共享内存，省去通用寄存器中转，因而有机会在计算当前 tile 时载入下一块。

Hopper 的 FP8、warpgroup 矩阵乘与 TMA 异步搬运

Hopper 把协作发令的单位从一个 warp 扩大到四个 warp 组成的 warpgroup。它们共同发 wgmma 指令；FP16/BF16 常见 tile 为 64×N×1664\times N\times1664×N×16，TF32 的 K=8K=8K=8，FP8 的 K=32K=32K=32。BBB 来自共享内存，AAA 按指令形式可来自共享内存或寄存器，累加器在寄存器中。张量内存加速器（TMA）按描述符把多维 tile 搬入共享内存，生产数据的 warp 和消费数据的 warpgroup 通过屏障对齐进度。线程块簇还可以访问簇内其他块的共享内存。

FP8 增加 E4M3 和 E5M2 两种取舍，论文中的常见方案用前者保存权重与激活、后者保存梯度，再配合缩放和更宽累加。H100 SXM 的手册给 BF16 与 FP8 的稀疏值 1,979 和 3,958 TFLOPS；折回稠密约为 989 和 1,979 TFLOPS。做持续吞吐对照还要看板型，SXM 的功耗上限可到 700 W，H100 NVL 的范围为 350–400 W。

Blackwell 的低精度矩阵乘与张量内存支持范围

B200（计算能力 10.0）和 Jetson Thor（11.0）都允许单个线程发出 tcgen05.mma。要针对这两款芯片编译，可以分别选用架构专用目标 sm_100a 和 sm_110a。累加器迁入专用张量内存（TMEM），还可选两个 SM 协作：两边各取自己负责的 AAA，再交换分给彼此的半块 BBB。写 kernel 的人要规划 TMEM 分配、操作数暂存和两个线程块的同步。本系列其他文章使用的 RTX 5070 Laptop 属于消费级 sm_120，没有这条 tcgen05 或 TMEM 路径。即使在允许 FP4、FP6 及分块缩放的 sm_120a 上，仍然发 warp 级 mma。因此同属 Blackwell 的两个产品，实际能运行的程序可以不同。PTX 中 tcgen05.mma 支持的目标架构 · Thor 的 CUDA 计算能力说明

当操作数缩到 FP4、FP6 时，一小组数还可能共用一个缩放因子，节省数据空间的同时也要存储这些因子，并考虑它们对精度的影响。HGX B200 八卡系统的稠密 FP4 峰值约为 72 PFLOPS，FP8 约为 36 PFLOPS，BF16 约为 18 PFLOPS。产品表中部分数值采用结构化稀疏口径，要折半才可与这里的稠密峰值比较。表中 1.8 TB/s 的 NVLink 带宽则是每张 GPU 的指标。

大矩阵乘与单 token 解码的计算及带宽下界

以同一张 A100 为例，三条边长均为 4,096 的半精度方阵乘法要处理两个输入和一个输出，理想数据量约 100 MB，计算量约 1.37×10111.37\times10^{11}1.37×1011 FLOP。按 A100 的稠密峰值，计算至少要 0.44 ms；按 2,039 GB/s 的 HBM 峰值，理想流量至少要 0.05 ms。若换成生成单个 token 的矩阵向量乘法，仍要读约 33.5 MB 权重，计算量却只剩原来的 1/40961/40961/4096，矩阵单元即使更快，也很难把时间下界推低。用屋顶线判断算力和带宽的约束

从 Volta 到 Blackwell，较窄的格式使每字节能携带更多操作数，较大的 tile 使一次读取服务更多乘加，而异步搬运允许下一块数据提前就位。要将这些变化换成某个 kernel 的耗时，需要按板卡、时钟、精度与稀疏条件选取峰值，再检查真实形状能否提供足够的分块、复用和流水重叠。
