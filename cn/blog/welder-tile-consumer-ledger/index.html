生产者与消费者的算子融合：从中间张量复用到 tile 调度

两个相邻的 8×8 卷积输出块都要用到同样的两列输入，把上游计算并入各自的线程块，就会把这两列各算两遍。卷积后接 ReLU 时，融合能省去 ReLU 对中间张量的一次读取，但如果另一条支路在单独的核函数里读取完整的卷积结果，生产者仍须写回整张张量。

假设相邻的两个 8×88\times88×8 卷积输出块各由一个 CUDA 线程块计算。让每个线程块自己生成所需的输入，就可以直接在片上读这些中间结果。代价是两个输出块重叠的输入也会跟着算两遍。还有另一种情况需要单独算：如果另一条支路交给单独的核函数处理，还要从全局内存读取整张卷积输出，那么即使当前线程块已经用过这些结果，也得为那条支路把它们写回去。

Welder 从输出块反推所需的输入坐标，因为坐标重叠的范围决定了融合后会重复多少计算。它还要沿算子图检查谁会读这些结果，才能决定结果可留在哪一级存储。下面的卷积和 ReLU 分别给出这两个判断所需的信息。Welder 论文 §§3.1–3.2

相邻卷积输出块的输入重叠与重复计算

设下游是步幅 1、无膨胀的 3×33\times33×3 卷积，两个输出块都在图像内部。把左块需要的第一列输入编号为 0。它要产生八列输出，卷积窗从左向右移动八个位置，一共覆盖输入的第 0～9 列。右块的起点往后挪了八列，覆盖第 8～17 列。纵向上，两个块需要的都是相同的十行。

图 1　每个格子代表一个输入通道中的一个空间位置。深色的第 8、9 列会同时参与左右两个块的计算。为了覆盖边缘输出而向外多取的一圈输入，通常称为 halo。

每个输出块需要 10×10=10010\times10=10010×10=100 个输入位置，两块合起来只有 10×18=18010\times18=18010×18=180 个不同位置。若让两个线程块各自计算上游结果，同一片重叠区域就会被算两遍。总共生产的 200 个位置中有 20 个重复，恰占 10%。

增大输出块以后，边缘重复计算所占的比例会下降。若输出边长为 bbb，两个块各自计算所需输入，一共要算 2(b+2)22(b+2)^22(b+2)2 个位置，其中 2(b+2)2(b+2)2(b+2) 个位置两边都用得到。取 b=16b=16b=16，648 个位置中有 36 个重复，约占 5.6%。块变大也会占用更多片上空间。假设一个块要同时容纳所有输入，每个位置有 256 个 FP16 通道，单块输入占用就会从 b=8b=8b=8 时的 50 KiB 增至 b=16b=16b=16 时的 162 KiB。如果沿通道分批处理，占用量也会随之变化。因此选择块大小时，还须确认能否放下同时要用的数据。

第二个消费者对卷积中间张量读写量的影响

为了单独看消费者数量的影响，可以把下游换成逐点 ReLU。位置 (y,x)(y,x)(y,x) 的 ReLU 只读同位置的卷积结果。若它是唯一的消费者，卷积线程块就能就地完成激活，只写最终输出，省去分开启动时对整张中间张量的一次写回和一次读入。

现在给同一份卷积输出再接一个单独启动的算子。ReLU 仍可在块内取值，但另一条支路要从全局地址读回整张张量。因此融合只省下 ReLU 的一次读，卷积输出仍需写回。

    P -->|写出| G["全局内存中的中间张量"]
    G -->|读取| S["另一个 kernel 中的第二个消费者"]

图 2　图中另加了一条支路，它需要激活前的卷积输出。即使卷积和 ReLU 已经融合，卷积仍须把原始结果写回全局内存，供这条支路读取。

在 VGG16 配置 D 中，从 224×224224\times224224×224 的输入出发，经过两次步幅为 2 的池化后，conv3_1 会产生 56×56×25656\times56\times25656×56×256 的输出。到 conv5_3 时已经过四次池化，输出缩小到 14×14×51214\times14\times51214×14×512。只处理一张图、用 FP16 保存中间张量时，这两层分别占 1,568 KiB 和 196 KiB（1 KiB 等于 1,024 字节）。下表分别计算每种形状能省下的读写量，每一列的比较双方都有相同数量的消费者。VGG 论文 §§2.1–2.2、表 1

这些数由张量形状和访问规则推导。全局读可以命中缓存，所以表里记的是逻辑访问量。一般地，假设 nnn 个消费者各完整读一遍，最初共需 (1+n)A(1+n)A(1+n)A：一次写出，加 nnn 次读入。把其中 kkk 个消费者移到片上，只要 k<nk<nk<n，就还需 (1+n−k)A(1+n-k)A(1+n−k)A。移入最后一个消费者时，才能连它的那次读和上游的那次写一起划掉。

Welder 调度器中的输入范围传播与访存估算

Welder 的默认 GPU 策略按逆拓扑序遍历算子图，这样处理生产者之前就已经知道消费者需要哪些输入。下面是 _compute_memory_traffic 里的代码，其中的方法名 propogate_inputs [sic] 沿用作者源码的拼写。Welder 默认调度策略

for node in reversed(self.ordered_nodes):
    tile = op_tile_map[node]
    input_shapes = node.propogate_inputs(tile)

对图 1 的卷积而言，消费者要计算 8×88\times88×8 的输出，就需要上游提供 10×1010\times1010×10 的输入。图 2 的 ReLU 逐点取值，需要的输入形状与输出相同。调度器沿着输入边反向传递这些形状，再结合分块大小和单次访存事务的粒度，估计融合组需要和外部交换多少数据。分配共享内存时，它还会追踪谁要用每个临时缓冲区，等最后一个消费者用完再回收。只有容量足够的方案才会按预计访问量进行比较，选出的方案还要实际计时。默认策略中的访存估计与临时存储 · Welder 论文图 7

给定一组候选分块，可以从输出坐标反推重叠区域，计算每一级存储同时要容纳多少数据，再沿消费者分支确定最后一次读发生在哪里。三者分别决定重算量、容量要求和能够省去的全局访问。这种按坐标判断复用范围的方法，同样适用于单个 GEMM 内部的分块。

枚举坐标、复算字节及重画输入图

用 Python 标准库就可以把两个输出块的所有卷积窗枚举一遍，拿集合运算交叉检查图 1。

def footprint(b, first_col):
    return {(row + dy, col + dx)
            for row in range(b) for col in range(first_col, first_col + b)
            for dy in range(3) for dx in range(3)}

a, b = footprint(8, 0), footprint(8, 8)
print(len(a) + len(b), len(a | b), len(a & b))  # 200, 180, 20

单个输入分块常驻 256 个 FP16 通道时，两种尺寸的逻辑存储量分别为 102×256×2=51,20010^2\times256\times2=51{,}200102×256×2=51,200 B 和 182×256×2=165,88818^2\times256\times2=165{,}888182×256×2=165,888 B。重复比例 1/(b+2)1/(b+2)1/(b+2) 对应文中两个水平方向相邻、位于图像内部的块。边缘填充、步幅或膨胀率改变后，需要重新求坐标集合。
