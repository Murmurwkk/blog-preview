在线 Softmax 注意力：分块归一化与跨查询行的 K/V 复用

在线 Softmax 为每行查询保留最大值、指数和与加权值向量，注意力内核就能边读 K/V 边累加，无须写出完整分数矩阵。在同一实现中把查询从每块一行增加到四行，2048 行查询时快约 1.29 倍，128 行时反而要花约 2.62 倍的时间。多行查询共用一份 K/V，也减少了可并行的独立线程块。

一行 Softmax 的分母取决于所有分数。把注意力按 K/V 分块时，线程块读到第一段还不知道后面会不会出现更大的分数，因此不能直接把当前概率当作最终权重。在线 Softmax 给每一段保留自己的归一化尺度，后续出现新的最大值时，只需重标定已经累积的结果。

以 M=N=2048M=N=2048M=N=2048 的单头自注意力为例，FP32 分数矩阵占 16 MiB。分离实现先将这块内存原地改写为概率，再由 PV 回读并计算加权和。若调用者只需要加权结果，在线实现可以在片上用掉一块概率后立即丢弃它。至于耗时能否随工作区一起下降，还取决于多行查询能复用多少 K/V，以及网格中是否保留了足够多的独立块。

在 RTX 5070 Laptop（SM120）上，我用独立的 CPU FP64 参考结果核对了各版输出。显式写出矩阵的实现提供完整注意力的计时对照，旧的一行版则用来区分内核重写和跨查询行复用 K/V 的影响。两种接口也有一道重要区别。注意力只需返回加权向量，消费完 K/V 块就能释放它；如果要求写出整行 Softmax 概率，算出全行分母后，每列仍要再取回自己的分数。

这里计算单头稠密注意力的前向传播。Q∈RM×dQ\in\mathbb R^{M\times d}Q∈RM×d 和 K,V∈RN×dK,V\in\mathbb R^{N\times d}K,V∈RN×d 均按连续 FP32 数组存储，MMM 是查询行数，NNN 是键和值的行数，ddd 是特征维度。实现不加注意力掩码或 dropout，也没有反向传播。

稳定 Softmax 会先减去最大值以限制指数范围。在线归约还用这个最大值表示整块的尺度，有了它，两段分别累积的结果就能换算到同一基准。

m=max⁡jsj,ℓ=∑jesj−m,pj=esj−m/ℓ.m=\max_j s_j,\qquad \ell=\sum_j e^{s_j-m},\qquad p_j=e^{s_j-m}/\ell.m=jmax​sj​,ℓ=j∑​esj​−m,pj​=esj​−m/ℓ.

分子与分母同除 eme^mem，各项的概率在精确算术下保持不变。只要分数都是有限值，减去最大值后，指数函数的输入就不会大于零，从而避免因输入过大而溢出。若允许分数取正无穷，则须额外规定 ∞−∞\infty-\infty∞−∞ 如何处理。

将两段状态重标定到同一个最大值

设一行的三个分数依次为 0、1、3。读完前两项时，最大值为 1，对应指数和为 e−1+1e^{-1}+1e−1+1。最后一项把最大值抬高到 3，同样的前两项若以 3 为基准，指数和就变为

(e−1+1)e−2+1=e−3+e−2+1.(e^{-1}+1)e^{-2}+1=e^{-3}+e^{-2}+1.(e−1+1)e−2+1=e−3+e−2+1.

只要把已有的整块指数和乘以 e−2e^{-2}e−2，就能从旧最大值 1 换到新最大值 3，无须重新读取前两项。把这一步抽象出来，任意一个处理过的集合 AAA 存两个数

mA=max⁡j∈Asj,ℓA=∑j∈Aesj−mA.m_A=\max_{j\in A}s_j,\qquad \ell_A=\sum_{j\in A}e^{s_j-m_A}.mA​=j∈Amax​sj​,ℓA​=j∈A∑​esj​−mA​.

另一块 BBB 也记录了自己的最大值与指数和。合并时取两个最大值中的较大者作为公共尺度，将两块的指数和各自换算到这个尺度后相加。

m=max⁡(mA,mB),ℓ=emA−mℓA+emB−mℓB.m=\max(m_A,m_B),\qquad \ell=e^{m_A-m}\ell_A+e^{m_B-m}\ell_B.m=max(mA​,mB​),ℓ=emA​−mℓA​+emB​−mℓB​.

共同尺度取两个旧最大值中较大的一个，因此换算系数都不超过 1，重标定不会放大任一块已有的指数和。合并得到的正是并集的最大值与指数和，所以在精确算术下，顺序读取和树形归约会得到相同结果。CUDA 可以让线程、warp 和 block 分层合并这些状态，但在浮点算术下，加法顺序仍会影响末位。Online normalizer 论文

注意力还要求加权输出。因此除了分母，每个分块还要保存一条 ddd 维向量，累积相同权重作用在值向量上所得的分子。

uA=∑j∈Aesj−mAVj.u_A=\sum_{j\in A}e^{s_j-m_A}V_j.uA​=j∈A∑​esj​−mA​Vj​.

加权分子与指数和来自同一组分数。两块的分子也必须分别乘以上式中对应的换算系数，才能在相同尺度上相加。

u=emA−muA+emB−muB,O=u/ℓ.u=e^{m_A-m}u_A+e^{m_B-m}u_B, \qquad O=u/\ell.u=emA​−muA​+emB​−muB​,O=u/ℓ.

如果调用者只需要注意力输出，线程读到 VVV 时就可以把贡献计入 uuu，随后丢弃当前块的分数。每行只留下两个标量和一条 ddd 维向量，无须保存全部 NNN 个概率。FlashAttention 将这套在线归一化与片上矩阵分块结合，省去了完整注意力矩阵的写回与重读；最终耗时还要看输入复用与并行分工。FlashAttention

每个线程块处理一行查询的 CUDA 实现

第一版 CUDA 实现让一个线程块的 128 个线程共同处理一行查询。它们把查询留在共享内存中，沿 NNN 分块读入 K/VK/VK/V。每个块内有四个 warp，各取一个键与查询做点积；同一 warp 的 lane 分摊 ddd 个通道，用 shuffle 合并部分和。等当前块的分数齐全，整个线程块求出最大值与指数和，各线程再累加自己负责的输出分量。

以 d=64d=64d=64 为例：一个 warp 每 lane 负责两个乘积，归约完得到一个分数；四个 warp 并行算四个 key。到 PV 阶段，线程改按输出特征维分工，前 64 个线程各累加一个有效维度，用同一份分数权重、读各自的 VVV 列，最后写出这个 query 的 64 维输出。

融合更新不必单独存当前块的 uBu_BuB​，直接在共同尺度上累加：

new_m = max(old_m, tile_max);
alpha = exp(old_m - new_m);
for (each valid key j in this tile)
    p[j] = exp(score[j] - new_m);

acc = alpha * acc + sum_j(p[j] * V[j]);
l   = alpha * l   + sum_j(p[j]);
m   = new_m;
// 遍历全部 K/V tile 后：
output = acc / l;

acc 是 ddd 维向量。最大值 mmm 和分母 ℓ\ellℓ 由线程块共享，输出分量留在各线程的寄存器里。实现用 fmaf 做乘加、__expf 求近似指数，旧状态初始化为 (-FLT_MAX,0,0)。N>0N>0N>0 保证每个处理的 tile 都有有效 key。即使没有打开 --use_fast_math，__expf 本身仍是近似运算。在线单头 attention 的 CUDA 实现

尾块掩码、空归约哨兵与共享内存竞争

第一次错误来自尾块填充。GEMM 沿 KKK 补零只会增加乘积为零的项，Softmax 却会给补成零的假分数分配正权重，分母也随之改变。因此最后一块沿 NNN 只能处理 min(TileN,N-tile_start) 个真正存在的 key。

另一个错误源于分离实现把 -FLT_MAX 当成空状态的标记，用 max_next > -FLT_MAX 判断线程是否读到输入。这个数本身是合法的有限分数。取 d=1d=1d=1、QQQ 全为 -FLT_MAX、KKK 全为 1，每个分数恰好等于这个合法有限值，非空线程被当成空线程。M=3M=3M=3、N=2N=2N=2、d=1d=1d=1 时每行两个概率都变成 1，行和成了 2，最终 OOO 的最大误差 0.108322。判据改成 sum_next > 0 才正确：NNN 非空时指数和一定大于零，这与前面「ℓ>0\ell>0ℓ>0 说明集合非空」是同一个性质。N=2N=2N=2、33、257 分别覆盖小行、跨 warp 和跨线程步进。

第三处错误发生在最大值与指数和归约共用的共享内存临时区。归约函数让 warp 0 写入本轮结果，再让整个线程块通过屏障。旧实现在屏障后立即返回共享内存中的值。

__syncthreads();
return scratch[0];

这道屏障保证之前的写入对所有线程可见，却没有要求它们同时读完。快的 warp 返回后可以进入下一次求和归约并覆盖临时区，慢的 warp 此时才来取上一次的最大值。单看源代码，两次函数调用确实按顺序出现；跨 warp 复用同一地址却还缺一道同步。

修复后的函数把结果读入各线程的局部变量，等所有线程都通过第二道屏障才返回，使下一次归约可以安全地复用临时区。

__syncthreads();
const float result = scratch[0];
__syncthreads();
return result;

128 个线程全都调用这个 helper，所以第二个屏障合法；若有线程跳过它，参与范围要重新设计。给 max、sum 各分一块 scratch 也可行，只是那两段存储的生命周期要重新定义。

未修复版本通过了本次 72 项常规输出比较，但 racecheck 在 31×37×6531\times37\times6531×37×65 上报了 9 个 hazard，4 个 error、5 个 warning，那次最大输出误差 0.171574。修完同一份输入，误差是 7.9103×10−87.9103\times10^{-8}7.9103×10−8，memcheck、racecheck、synccheck 分别是零错误、零 hazard、零错误。普通输入偶尔算对，替代不了对共享存储读写顺序的检查。

融合注意力省去的分数矩阵与转置工作区

修好归约后，可以先按内存分配计算融合节省的空间。分离实现为 FP32 分数矩阵和转置后的 K 各预留一块全局工作区。令 MMM 为查询行数、NNN 为可见键数、ddd 为通道数，它需要的全局临时空间为

Wseparated=4MN+4Ndbytes.W_{\rm separated}=4MN+4Nd\quad\text{bytes}.Wseparated​=4MN+4Ndbytes.

固定 K/V 块宽时每块处理 1、2 或 4 行查询的耗时

省去分数矩阵以后，单查询内核仍有一项重复工作：负责不同查询的线程块各自遍历相同的 K/V。为了测这项复用，我写了 online_rows<Bq>，把每块的查询行数 BqB_qBq​ 设为 1、2 或 4，统一用 TileN=32、128 个线程、FP32 和同一条在线递推。每读进一个 K/V 块，block 依次处理它负责的查询行，再去取下一块。这样可以共用加载，但多行的输出累加器得同时保活，grid 也跟着缩小。这里逐行算点积，没有换成矩阵乘微内核。

K/V 块宽对共享内存用量与耗时的影响

前面的对照固定 K/V 块宽，只改每块的查询行数。较早的实验则固定每块一行查询，在容量允许时自动选 TileN128，并与 TileN32 比较。d=64d=64d=64 时它申请 66,320 B 动态共享内存，TileN32 只需 16,784 B。旧方阵测量中改为 TileN32 明显加快。另在 M=128,N=2048,d=64M=128,N=2048,d=64M=128,N=2048,d=64，NCU 给出的 shared 限制分别是 TileN32 每 SM 可驻 5 块、TileN128 可驻 1 块，实测占用率 29.66% 和 8.33%。全局加载请求与扇区数完全相同，两版的额外 shared wavefront 也都是零。切换 K/V 块宽会改变循环结构和驻留条件。在前面的跨查询行对照中，两者都使用 TileN32，以固定这一维度。

还有一项旧对照是把 100 次调用中的 200 次动态共享内存属性设置挪到计时前。挪动前后 TileN128 的单 kernel 活动中位数都约 2,040.8 µs，TileN32 都约 643.3 µs。反复设属性不足以解释当时的巨大差距。历史图中的批次百分位和这次独立进程的置信区间采用两套统计口径。

完整 Softmax 概率的两遍扫描

注意力只返回加权值向量，因此当前块的分数用过就能丢弃。若接口要求写出整行 softmax 概率，(m,ℓ)(m,\ell)(m,ℓ) 虽能给出分母，却无法恢复每列原来的分数。除非整行都留在片上，拿到最终分母后就需要重读输入。

当一行有 10610^6106 个元素时，若只启动一个线程块，其余 SM 就无法分担这一行的计算。第一段可以让 GGG 个线程块各自扫描部分输入、求局部状态，第二段再据此写出各自负责的概率。两个 kernel 都采用每块 512 个线程。两阶段长行 softmax 的 CUDA 实现

第二段把归约与输出放进同一个 kernel。每个输出线程块的 warp 0 都重新合并全部 GGG 个局部状态，把整行的最大值与分母写入本块的共享内存，其他线程才能用它们归一化各自负责的输入。

if (threadIdx.x < 32) {
    for (int i = threadIdx.x; i < num_blocks; i += 32) {
        float m = block_max[i], s = block_sum[i];
        // 合并到线程局部状态，再在 warp 0 内归约。
    }
}

这样省掉一次 kernel 启动，代价是统计量读取按 G2G^2G2 增长。固定 N=1000000N=1000000N=1000000、G=144G=144G=144，NCU 给出第一段 7813 个 global load request、125000 个 sector，第二段 9253、130184。差值能直接从代码算出：

Δrequest=144×2×⌈144/32⌉=1440,\Delta request=144\times2\times\lceil144/32\rceil=1440,Δrequest=144×2×⌈144/32⌉=1440, Δsector=144×2×144×432=5184.\Delta sector=144\times\frac{2\times144\times4}{32}=5184.Δsector=144×322×144×4​=5184.

两组连续 FP32 统计量各 144 项，每个输出 block 都读一遍；相减结果与采样一致。这里说的是 L1TEX 请求和 sector，不是等量的 DRAM 流量，重复的统计量还能命中缓存。因此多开 block 提高输入扫描并行度的同时，也多了重复合并，这份实现无法靠加 block 无限加速。

反汇编里，对齐输入用 ld.global.v4.b32，warp 合并用 shfl.sync.down.b32，指数生成 ex2.approx.f32，SASS 对应 MUFU.EX2。自然指数先乘 log⁡2e\log_2 elog2​e 转成二进制指数；近似指数加上归约树，就是实数状态公式落到 FP32 时的具体误差来源。两段都没有额外 shared wavefront，也没有运行时 spilling 请求，长行 occupancy 约 85.85%、86.33%。短行只有一个 block，用局部驻留百分比说明不了整张 GPU 有多忙。

并发请求之间的 Softmax 工作区隔离

两个 kernel 之间必须传递同一行的最大值与指数和。多个请求并发时，若复用同一份状态数组，后一行就可能覆盖前一行还没用完的数据。若用一个所有调用共用的 global 数组，两条长度 65537 的行 A=0、B=10，按 A第一段→B第一段→A第二段→B第二段 排一次，B 就会把 A 的最大值和指数和盖掉，A 输出的行和变成 e−10≈4.53999×10−5e^{-10}\approx4.53999\times10^{-5}e−10≈4.53999×10−5。这是人为排出的阶段交错，说明共享状态不适合直接暴露成并发接口，并不代表原来那个同步 solve 每次都会出事。

新接口由调用者传入执行用的 stream，并为每个在途请求提供独立工作区。工作区要能容纳 2*G 个 float，以便两次启动传递各块的最大值与指数和。

cudaError_t softmax_vector_launch(
    const float* input, float* output, int N,
    float* workspace, int num_blocks, cudaStream_t stream);

工作区从第一段启动前一直保留到第二段结束，不能与输入或输出重叠。不同在途请求各自使用一份工作区，输入与输出可以完全同址，但不能只重叠一部分。长行实现用 (-FLT_MAX,0) 表示空状态；两个空块合并时，相减的是两个相等的有限最大值，指数输入为零。分离注意力实现另用指数和判断非空，两种判据对应各自的合并代码。

在线归一化下的 K/V 复用与查询并行度

在线递推为每行查询保留两个标量和一条 ddd 维向量，足以算出加权输出，无须写出完整分数矩阵。让四行查询共用一个线程块会减少 K/V 读取，也会减少可并行的独立块数。在 M=2048M=2048M=2048 上，Bq4 快于同模板的单行版；到 M=128M=128M=128 或只有一行查询时，Bq4 都更慢。在直接配对的两个多查询形状上，Bq4 的耗时也都高于显式矩阵的手写对照。Bq1、Bq2 与显式矩阵没有直接配对。对于必须输出每一列概率的另一种接口，若整行输入无法留在片上，确定最终分母后仍需重读分数。
