Tensor Core 的 TF32 矩阵乘：输入舍入、FP32 累加与吞吐量

TF32 会先将乘法输入舍入，再用 FP32 累加。让普通 CUDA 核函数也读取舍入后的矩阵，长点积仍可能只有 WMMA 超出误差预算。在 RTX 5070 Laptop 上，分块 WMMA 算 128³ 方阵约快一倍，算 1024³ 和 2048³ 方阵却比 FP32 SIMT 更慢。

在 RTX 5070 Laptop 上做一组 32×32 输出、归约长度 K=8192K=8192K=8192 的矩阵乘法时，我给输入取了随机尾数，并让它们分布在多个二进制指数上。对这批输入，两份 WMMA 实现各有 639 个输出超过了事先定下的误差预算。这听起来像 TF32 舍掉输入尾数的必然后果。但我在 CPU 上把输入独立舍入到同样的 TF32 精度，交给普通 SIMT 核函数，1024 个输出全部通过。输入表示相同，后面的计算路径仍然能改变答案。

降低输入精度能不能换来速度，还要看矩阵形状。同一张笔记本显卡上，分块 WMMA 算 128³ 方阵时比 SIMT 快，到 1024³ 却多花了约 52% 的时间。比较速度之前，得先知道这两条路径各自算出了什么。下面这个点积在 FP32 下的精确结果是 1，只改输入的表示方式，它就会变成 0。

FP32 存储与 TF32 乘法输入的 11 位有效精度

一个正常 FP32 数占 32 位，其中 1 位表示符号、8 位表示指数、23 位保存小数部分。再算上隐含的首位，有效精度是 24 位。TF32 同样有 1 位符号和 8 位指数，小数部分却只有 10 位，所以常被称为 19 位格式，加上隐含首位后的有效精度是 11 位。这个数说的是乘法器能区分多细的差别，不能据此推算显存里每个元素占多少字节。

两份实现都从显存读取以 FP32 存储的 A、B，每个元素占四字节，但舍入发生在不同位置。warp 版读入元素后先舍入，再把它写入共享内存。线程块分块版先把原值搬进共享内存，等各 warp 把它们装进寄存器中的 fragment 后才舍入。两条路径都以四字节保存操作数，实际要搬多少数据还取决于同一块输入能被多少个 warp 复用。

其次是舍入间隔与误差界的关系。在 [1,2) 区间内，FP32 相邻可表示值的间隔是 2−232^{-23}2−23，TF32 是 2−102^{-10}2−10。这里的 2−102^{-10}2−10 是相邻数的绝对间距。取最近可表示值时，这一区间的绝对舍入误差至多为半个间距，也就是 2−112^{-11}2−11。到了下一个二进制指数区间，间距和误差上界都会翻倍。

输入舍入在抵消点积中消去的差值

为了把少掉的有效位同最终输出联系起来，可以构造一个会发生抵消的点积。A 取 1+2−121+2^{-12}1+2−12 与 1，B 取 1 与 −1，四个数在 FP32 中都能精确表示，原始乘积之和为

(1+2−12)⋅1+1⋅(−1)=2−12.(1+2^{-12})\cdot1+1\cdot(-1)=2^{-12}.(1+2−12)⋅1+1⋅(−1)=2−12.

1+2−121+2^{-12}1+2−12 与 TF32 可表示的 1 之间的间隔只有四分之一步长（该区间步长为 2−102^{-10}2−10），舍入后即为 1，差值消失。把这一对重复 4096 次，点积长度 8192，原始结果恰好为 1，按转换后的输入计算恰好为 0。

实测与手算一致：SIMT FP32 与 cuBLAS pedantic FP32 得到 1，两份 WMMA 都得到 0。返回类型是 float，累加器也确实声明为 FP32，但乘法输入的有效位已经损失，后续累加无法恢复。

这个输入的作用是放大误差的相对尺度。此处 ∑k∣akbk∣=8193\sum_k|a_kb_k|=8193∑k​∣ak​bk​∣=8193，而 ∣∑kakbk∣=1|\sum_k a_kb_k|=1∣∑k​ak​bk​∣=1，扰动相对每一项都很小，相对最终结果的误差最多可被这种抵消放大 8193 倍，属于灾难性抵消。随机矩阵很少命中这种结构，这也是它容易被常规精度测试漏掉的原因。

TF32 转换的中点舍入规则：RNA 与 RNE

要独立复算这次舍入，除了知道 TF32 的有效位数，还需确认恰好落在两个可表示值中间时 GPU 会选哪一侧。本机 Toolkit 13.1 的 wmma::__float_to_tf32 走 cvt.rna.tf32.f32，RNA 指 round to nearest, ties away from zero，即取最近值、中点远离零。它与 IEEE 默认的 RNE（最近偶数）并不等价：1+2−111+2^{-11}1+2−11 恰好位于 1 与 1+2−101+2^{-10}1+2−10 的中点，RNA 取 1+2−101+2^{-10}1+2−10，RNE 取 1，因为 1 的尾数末位为偶数。

这个差别会影响「独立参考」的定义。以 RNE 写 CPU 参考再与 GPU 比较，会得到一批本不该出现的差异。PTX 的舍入修饰符

我用两条独立路径核对中点舍入。CPU 端用 frexp 把绝对值写成 f×2^e（0.5≤f<1），将 f×2^11 按 RNA 舍入到整数，再乘回 2^(e-11) 并恢复符号。GPU 端只调用实际的转换指令，导出结果的位模式。262144 个随机正常数、6144 个正负中点及相邻 FP32 数，再加正负零，合计 268290 个输入，两端逐位一致。

该 CPU 模型只覆盖所测的正常数与零，NaN payload、次正规数、溢出边界不在验证范围内，代码与范围见文末。

warp 内 16×16×8 矩阵块的 WMMA 分工

普通单指令多线程（SIMT）矩阵乘法让线程各自持有标量累加器并执行 fmaf。换用 warp 级矩阵乘加接口（WMMA）以后，32 个线程协作计算一个子块，操作数和部分和以 fragment 的形式分布在整个 warp 的寄存器里。对齐、同步与矩阵坐标映射都应以这组线程为单位来理解。

这里使用 16×16×8 的 TF32 形状：A 子块 16×8，B 为 8×16，输出与累加块 16×16。这些维度属于整个 warp，不能按单线程理解。接口核心只有几步，示例省略 global→shared 的搬运：

using namespace nvcuda;
wmma::fragment<wmma::matrix_a, 16,16,8,
               wmma::precision::tf32, wmma::row_major> a;
wmma::fragment<wmma::matrix_b, 16,16,8,
               wmma::precision::tf32, wmma::row_major> b;
wmma::fragment<wmma::accumulator, 16,16,8, float> c;
wmma::fill_fragment(c, 0.0f);

// shared 中的有效元素已转换为 TF32，无效边界元素已补零。
wmma::load_matrix_sync(a, shared_a, 8);
wmma::load_matrix_sync(b, shared_b, 16);
wmma::mma_sync(c, a, b, c);

这些协作操作要求整个 warp 以一致参数执行。fragment 中元素与矩阵坐标的映射不能按 lane 编号推断；若只对所有元素施加同一种转换，可以遍历 fragment.x。load_matrix_sync 的基址要求 32 字节对齐，float 的 leading dimension 需为 4 的倍数。WMMA 接口约定

warp 私有分块与线程块共享的操作数复用

两份 WMMA 实现的主要区别是哪些线程能复用同一块输入。第一份是 warp 版，每个 warp 负责一个 16×16 的输出块。八个 warp 同属一个线程块，却各自使用独立的 A、B、C 共享内存区域。沿 K 维每推进八项，warp 中的线程就一起读入并转换 A、B，等数据就绪后装入 fragment，执行矩阵乘加。算完所有 K 段以后，各 warp 把结果存回自己的共享内存，再由各线程写出有效位置。warp 版公开实现

其优点是数据归属简单，一个 warp 可独立完成一个 tile，边界容易核对。代价在复用：相邻 tile 不共享 A/B，两个 warp 即使计算同一行的不同列，A 子块也要各自加载。K=1024 需推进 128 段 K，重复加载、转换与同步随段数线性增长。

第二份 block 分块版的组织方式不同，block 输出放大到 64×64、BK=32，四个 warp 排成 2×2，每个负责 32×32。一个 warp 持有四个 16×16 累加 fragment，每个 k 步取两个 A fragment、两个 B fragment，做四次组合。A/B 由整个 block 合作加载，两个 shared 槽位让下一段 K 可异步搬运。block 分块版公开实现

它仍是矩阵乘法的分块复用，只是把线程间的标量外积换成 warp 协作的 MMA：输入进入 fragment 后逐元素转为 TF32，合法对齐的 global 片段走 cp.async，边界逐元素填充。两版对同一批原始值使用同一条转换规则。

让更多 warp 复用同一份输入，需要付出片上空间，第二份实现还要在共享内存中单独留出输出区域。这两版同时改变了分块大小、线程数、循环步长和数据复用范围。即使反汇编显示第二版用了 cp.async，两版的总耗时差也无法单独量出这条指令的贡献。

两版的输入输出契约相同：连续行主序 A[M,K]、B[K,N]、C[M,N]，K=0 写零；M/N/K 的尾部装 shared 时补零，合法输出逐项写回。warp 版在整块没有有效 tile 时该 warp 可以直接退出，但有效 warp 中没有合法 global 元素的 lane 仍需参与 WMMA。共同基址显式对齐到 32 字节，宽复制另查 16 字节要求。精确别名、任意 stride、非默认 stream 集成未纳入验证。

输入表示误差与舍入后计算误差的分解

同一批 FP32 输入可以产生两种偏差：先舍入到 TF32 改变了矩阵本身，随后执行乘法和累加又可能产生计算误差。只拿最终输出与原始矩阵的乘积比较，这两项会混在一起。若只比较舍入后的输入，前面点积从 1 变成 0 的变化又会消失。因此我在 CPU 上为同一批数据分别建立两份 FP64 参考。

C64=AB（原始 FP32 值转为 double 后计算）,C_{64}=AB\quad\text{（原始 FP32 值转为 double 后计算）},C64​=AB（原始 FP32 值转为 double 后计算）, Cq=Q(A)Q(B)（CPU 独立转换后以 double 计算）.C_q=Q(A)Q(B)\quad\text{（CPU 独立转换后以 double 计算）}.Cq​=Q(A)Q(B)（CPU 独立转换后以 double 计算）.

GPU 实际输出记作 C^\widehat CC，于是有

C^−C64=Cq−C64⏟Erep+C^−Cq⏟Eimpl.\widehat C-C_{64} =\underbrace{C_q-C_{64}}_{E_{\rm rep}} +\underbrace{\widehat C-C_q}_{E_{\rm impl}}.C−C64​=Erep​Cq​−C64​​​+Eimpl​C−Cq​​​.

ErepE_{\rm rep}Erep​ 衡量把原始输入舍入到 TF32 后，参考矩阵乘积偏了多少。EimplE_{\rm impl}Eimpl​ 则从同一份舍入输入出发，量出实际核函数和 FP64 参考之间的差距，乘积与累加的舍入次序、索引或实现错误都可能影响它。

第二段称为实现误差，并不表示它全部来自缺陷：Tensor Core 的舍入方式与累加顺序本来就可能不同于 CPU 的 FP64 循环。设置两份参考的目的，是让差异不再被输入降精度掩盖。极端例子是前述抵消输入，Eimpl=0E_{\rm impl}=0Eimpl​=0 而总误差为 −1，全部落在第一段。

这里还有一处容易算错：矩阵等式逐元素成立，但换算到 Frobenius 范数后两个范数不能直接相加，因为误差方向可能部分抵消。下文所有相对范数统一除以原始 C64C_{64}C64​ 的范数，零参考另行保留绝对误差。

SIMT FP32 与 cuBLAS pedantic 没有 Q 这一步，直接对原始 C64C_{64}C64​ 检验。基础集合覆盖随机、可精确表示、抵消、中点、动态范围、全零六类输入，加 12 个形状、尾部与偏移，四实现共 288 项，各自在自己的目标输入上通过预算。

长归约维度下的 WMMA 误差

归约越长，乘加次序和舍入误差越有机会影响最终结果，因此长 K 单独测试。输出固定 32×32，K 从 8 增到 8192，1024 个输出仍可做完整 FP64 参考。四类输入、六个 K、四实现共 96 项，逐元素预算事先固定：

∣C^ij−Ctarget,ij∣≤10−6+16ϵ32∑k∣Atarget,ikBtarget,kj∣.|\widehat C_{ij}-C_{{\rm target},ij}| \le 10^{-6}+16\epsilon_{32}\sum_k|A_{{\rm target},ik}B_{{\rm target},kj}|.∣Cij​−Ctarget,ij​∣≤10−6+16ϵ32​k∑​∣Atarget,ik​Btarget,kj​∣.

WMMA 的 target 是 Q(A)、Q(B)，FP32 对照的 target 是原始输入。这是本实验的验收阈值，不是 CUDA 对任意 K 的误差定理，也不是把 TF32 表示误差计入后才放宽的容差。

随机输入 K=8192 时两版 WMMA 统计一致：总相对 Frobenius 误差约 2.60×10−42.60\times10^{-4}2.60×10−4，其中表示误差约 2.58×10−42.58\times10^{-4}2.58×10−4，实现误差约 3.76×10−53.76\times10^{-5}3.76×10−5。总误差在 10−410^{-4}10−4 附近变化不大，实现误差这一段却已从短 K 的 10−810^{-8}10−8 量级上升，只观察总误差会漏掉这一变化。同一批输入下 SIMT 与 cuBLAS 的最终相对误差分别约 1.56×10−61.56\times10^{-6}1.56×10−6 与 2.52×10−72.52\times10^{-7}2.52×10−7。

SM120 的矩阵指令与分块资源开销

测量完整 kernel 之前，先核对两份 WMMA 实际生成了哪些转换与矩阵乘加指令。CUDA 13.1、-arch=sm_120 编出的 PTX 中包含：

cvt.rna.tf32.f32 ...;
wmma.load.a.sync.aligned.row.m16n16k8.tf32 ...;
wmma.load.b.sync.aligned.row.m16n16k8.tf32 ...;
wmma.mma.sync.aligned.row.row.m16n16k8.f32.tf32.tf32.f32 ...;

最后一行依次给出结果、A、B 和累加输入的类型，表示乘法读入 TF32，累加保留 FP32。反汇编得到的 SASS 中，对应的机器指令是 HMMA.1684.F32.TF32，一条 PTX 矩阵操作会展开成多条这样的指令。在程序文本里，warp 版有四处 HMMA，block 版有十六处，后者还能找到 LDGSTS.E.BYPASS.128。SIMT 基线执行的则是 FFMA。

反汇编表统计的是代码中出现这些指令的位置。要估计一次调用执行了多少次 HMMA，需要动态计数。要估计 SM120 的矩阵吞吐，也须使用这一设备对应精度的上限，Hopper WGMMA 和 SM100 的规格属于其他指令路径。

在四个尺寸上，能在线程块内共享输入的 block 版都比 warp 版快。若改和 SIMT 比，1024³ 与 2048³ 的 block 版却分别慢约 13.7% 与 13.3%。在这批单独的设备计时中，这两个尺寸既损失了输入精度，也没有获得加速。cuBLAS 对照关闭了 fast TF32，这组数据也未覆盖用多次 TF32 分解维持精度的库实现，因此它给不出 Tensor Core 的性能上限。

128³ 的情形相反，block 版 0.01212 ms，快于两份 FP32 对照；缩小到 16×16×8 时，warp 版约 8.34 µs、block 版约 9.05 µs，更大的协作组织失去优势。选型需要按形状判断，仅依据是否使用 Tensor Core 不足以下结论。

设备计时提前选定 kernel，保留 kernel 内的 TF32 转换，排除公开入口反复查询设备属性的开销。若按公开接口执行一次主机上传、运算、下载与同步，1024³ 的等待时间为 SIMT 1.663 ms、warp 2.044 ms、block 1.548 ms、cuBLAS 1.487 ms，不含分配、编译与 handle 创建。

四条路径都传输 float，因此主机往返还会包含相同格式的上传和下载，而单次测量本身波动较大。对于数据常驻 GPU 的任务，可以使用设备时间比较 block WMMA 和 SIMT。若应用每次都从主机上传输入，则要按应用实际的往返流程计算等待时间。

TF32 的误差容限与适用矩阵尺寸

选择 TF32 前，可以用两份参考依次回答两个问题。将输入舍入后，理想矩阵乘积的偏移是否仍在任务允许的范围内？如果可以，实际核函数用这些输入算出的结果又能否满足误差预算？例如开头那个点积如果必须保留结果 1，输入一经舍入就已经丢掉所需精度，无须靠计时来决定是否选用它。这组点积也没有单独计时。对于能接受输入舍入的任务，还要在实际矩阵形状上比较两条路径的完整耗时。

转换模型

转换参考对应本机 CUDA Toolkit 13.1 include/crt/mma.h 中的 cvt.rna.tf32.f32，遵守 PTX 的最近值、平局远离零规则。

CPU 模型用 frexp 将绝对值写成 f×2^e，其中 0.5≤f<1；将 f×2^11 舍入到整数，平局取更大绝对值，再乘回 2^(e-11) 并恢复符号，不直接复制 GPU 位编码：

int exponent;
double frac = frexp(abs(double(x)), &exponent);
double significand = floor(ldexp(frac, 11) + 0.5);
float q = copysign(float(ldexp(significand, exponent - 11)), x);

这只是本实验有限正常数与零范围内的数值模型，不是所有架构、所有 TF32 存储形式的通用标准库实现。NaN payload、无穷、次正规数、溢出边界都没有靠这段模型一并获得验证。

随后用单独的 GPU 转换 kernel，只调用实际 intrinsic 并导出结果位模式，与 CPU 模型逐位比较：262,144 个随机正常数，6,144 个正负 midpoint 及相邻 FP32 值，再加正负零，合计 268,290 项，零不一致。随机正常数的二进制指数覆盖 -80 至 80。部分原始探针如下，都是 FP32 位模式：

输入CPU RNA 模型GPU intrinsic含义
3f800fff3f8000003f800000低于第一个中点
3f8010003f8020003f802000恰在中点，向更大绝对值舍入
3f8010013f8020003f802000高于中点

例如 1+2^-11 在这里会变成 1+2^-10；RNE 对这个特定中点会选 1。这个差异平时很容易被随机测试漏掉，却会让「独立参考」的含义发生变化。

计时协议与环境

基础正确性集合使用 12 个形状检查索引和尾部：K=0/1/3/7/8/9/31/32/33/64/65/129，加上 M/N 尾块和 0–3 个 float 指针偏移。均匀随机、TF32 可精确表示的八分数、成对抵消、中点舍入、随机尾数乘 2^[-10,10]、全零 A 六类输入，共四实现 288 项，均通过对应参考与固定预算。

性能集合使用固定种子的均匀随机输入，覆盖 16×16×8、128³、512³、1024³、2048³，以及指针偏移一个 float 的 129×131×65。四实现、六形状、三轮，共 72 个计时任务，每个任务在计时前验证结果。大形状检查 257 个 CPU FP64 位置，并以完整 cuBLAS pedantic FP32 计算对应精度的目标：WMMA 使用 CPU 独立 Q 后的输入，FP32 使用原始输入。大矩阵没有做完整 CPU FP64 参考。

设备批计时使用 20 次预热、10 次 pilot、每批目标约 20 ms、每批 1–2000 次重复、30 批、3 轮，轮内任务顺序随机打乱。输入重复使用、不清 L2，笔记本不锁频。图表报告三轮中位数的中位数，误差线为三轮中位数范围，不是统计置信区间。

设备计时提前选择 WMMA kernel；端到端计时保留公开 launch 的设备属性查询。两种计时都包含 kernel 内的 TF32 转换。

测试设备为 RTX 5070 Laptop/SM120、约 8 GB 显存，显示驱动 610.88，构建 Toolkit 13.1.115、MSVC 2022。环境查询分别为运行时 API 13.3、驱动 API 13.3、编译头文件 13.1，字段含义见 Windows CUDA 13 运行时版本说明。TF32 与前两篇 GEMM 分属独立测量批次，绝对时间不混合聚合。
