语言模型缩放律：训练算力、数据复用与推理成本的权衡

训练算力固定时，加大模型就要减少它能读到的词元数。公开训练记录表明，重复已有语料的收益也会逐渐下降。模型若要长期提供推理服务，额外训练一个较小模型，还可能比选择训练成本最低的配置更省总算力。

假设训练预算大致能支持两种方案：让 7B 模型处理 140B 个 token，或让 70B 模型只处理 14B 个 token。按稠密模型常用的计算量近似，两者需要的浮点运算量相当。

两种方案对算力的分配不同：前者用更多数据训练较小的模型，后者用更少的数据训练参数更多的模型。完整训练两者再比较，会把原本只能用于其中一种方案的预算花上两遍。扩展律（scaling laws）的用途，是先用较小规模的训练记录拟合损失与资源的关系，再据此预测哪种配置值得扩大。

开头的两种配置同时改变了参数量和训练数据量，因此单独知道扩大参数规模能带来多少改善，还不足以作出选择。如果训练语料用完了，重复阅读一遍旧数据能带来多少收益？如果训练后的模型还要长期提供推理服务，每次请求要付出多少计算？各篇扩展律论文给出的配比，只有放回各自的训练预算、语料约束和服务需求下才可比较。

验证交叉熵与训练计算量的定义

语言模型训练通常看验证集交叉熵：对正确的下一个 token，模型给的概率越高，负对数概率越小，再对大量 token 取平均。它比「一道题必须全对」的准确率平滑，也更容易看出规模规律。代价是平均预测损失和某项任务的准确率并不是同一个目标。

记 NNN 为稠密模型参数量，DDD 为训练实际处理的 token 总数。计算以参数矩阵乘法为主时，训练 FLOPs 常用

C≈6ND.C\approx6ND.C≈6ND.

每个 token 的前向约 2N2N2N 次浮点运算，反向约是前向的两倍，两项相加给出系数 6。这一近似忽略了长上下文注意力、激活重计算和通信，适合比较同类稠密模型的算术预算。若要换算 GPU 小时，还需知道硬件与实际吞吐；对于 MoE 或超长上下文，则应根据每个 token 实际使用的参数和注意力开销另作估算。

Kaplan 等人发现，在相当宽的观测范围内，验证损失会随规模扩大而近似按幂律下降。继续扩大规模仍有收益，但相同的增量带来的改善会越来越小。他们的算力分配分析偏向大模型，得到 N∗∝C0.73N^*\propto C^{0.73}N∗∝C0.73。实验主要用 WebText2，参数计数排除 embedding，大部分上下文 1024，规模到约 1.5B 非 embedding 参数。原论文 §2、§3、§6

Chinchilla 重新测量了不同模型大小与训练长度的组合。除了沿训练曲线找损失下包络，还直接比固定 FLOPs 下的不同配置，也就是 IsoFLOP 实验。400 多个模型从不到 70M 到超过 16B，训练量从 5B 到超过 400B token；三种估计方法给出的参数/数据增长指数约为 0.50/0.500.50/0.500.50/0.50、0.49/0.510.49/0.510.49/0.51、0.46/0.540.46/0.540.46/0.54。原论文 §3、表 2

Kaplan 与 Chinchilla 的训练长度和学习率日程

Kaplan 与 Chinchilla 在训练长度上的估计不同，其中一个可直接检验的差异是学习率日程。如果原计划训练 100B token，读到 20B 时保存的检查点可能仍使用较高的学习率。另一个模型若从一开始就计划训练 20B token，此时却已经完成学习率退火。尽管两个模型处理了同样多的 token，优化过程却处在不同阶段。

因此，如果用长训练在 20B 处保存的检查点估算“训练 20B token 能达到的损失”，就会把数据量的作用与学习率尚未完成退火的影响混在一起。Hoffmann 等专门研究了这种训练日程不匹配。将这些条件写全，实测的损失更接近

L(N,D;h,D,T),L(N,D;h,\mathcal D,\mathcal T),L(N,D;h,D,T),

hhh 包括训练方法和超参数，D\mathcal DD 是数据分布，T\mathcal TT 包含 tokenizer 与评价方式。写成 L(N,D)L(N,D)L(N,D)，是把这些条件固定或调好之后取的二维切片。

从同一个起点把预算加 1000 倍，参数指数 0.73 给出约 154.9 倍增长，指数 0.49 只给出约 29.5 倍。即使两条拟合曲线在已测范围内很接近，用它们估算大得多的预算时，所推荐的参数量仍可能相差数倍。

Llama 3 的作者为自己的训练设置重新估计了这条关系。他们对 40M 到 16B 的模型进行了固定计算量（IsoFLOP）扫描，预算从 6×10186\times10^{18}6×1018 到 102210^{22}1022 FLOPs；外推到 3.8×10253.8\times10^{25}3.8×1025 时，推荐约 402B 参数配 16.55T token，最后选了 405B。他们还另建了一层从正确答案负对数似然到任务准确率的映射，用来预测下游效果。Llama 3 §3.2.1，图 2 到 4

实际使用扩展律需要经过三个环节。先由实验估计损失随参数与数据的变化，再在固定预算对应的曲面上寻找最优配置，最后另行检验该损失对应怎样的任务表现。给定预算下的最优参数量只回答其中第二个问题。

固定训练算力下的最优参数量与词元数

用 Chinchilla 的参数化形式拟合验证损失后，可以直接求导，找出固定训练预算下最优的参数量和数据量：

L(N,D)=E+ANα+BDβ.L(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta}.L(N,D)=E+NαA​+DβB​.

A,B,E,α,βA,B,E,\alpha,\betaA,B,E,α,β 由训练结果拟合出来。EEE 是渐近项，另两项分别表示模型参数有限和训练数据有限时额外留下的损失。这个分解假定两种限制的影响可以分别计算后直接相加。Chinchilla §3.3、附录 D.2

固定预算 CCC 时 D=C/(6N)D=C/(6N)D=C/(6N)。同一预算下，模型参数量翻倍，能用于训练的 token 数就减半。将这个关系代入损失函数，得到

第一项随 NNN 变大而降，第二项随 NNN 变大而升。最低点满足

αAN−α=βBD−β.\alpha AN^{-\alpha} =\beta BD^{-\beta}.αAN−α=βBD−β.

等式的两边分别衡量按相同比例调整预算分配时，参数项与数据项带来的边际损失变化。因此求最优解时必须保留指数 α,β\alpha,\betaα,β，直接让两项损失相等并不能得到同一条件。解得

N∗(C)=(αAβB)1/(α+β)(C6)β/(α+β),N^*(C)= \left(\frac{\alpha A}{\beta B}\right)^{1/(\alpha+\beta)} \left(\frac C6\right)^{\beta/(\alpha+\beta)},N∗(C)=(βBαA​)1/(α+β)(6C​)β/(α+β), D∗(C)=(αAβB)−1/(α+β)(C6)α/(α+β).D^*(C)= \left(\frac{\alpha A}{\beta B}\right)^{-1/(\alpha+\beta)} \left(\frac C6\right)^{\alpha/(\alpha+\beta)}.D∗(C)=(βBαA​)−1/(α+β)(6C​)α/(α+β).

将这两个最优解相除，就能得到数据量与参数量的配比。只有 α=β\alpha=\betaα=β 时，参数和数据才都按 C\sqrt CC​ 涨，D/ND/ND/N 才是常数。一般情形下

D∗N∗∝C(α−β)/(α+β).\frac{D^*}{N^*}\propto C^{(\alpha-\beta)/(\alpha+\beta)}.N∗D∗​∝C(α−β)/(α+β).

常说的“每个参数配 20 个 token”是特定实验范围内的近似配比。方程本身既不要求该比值保持不变，也没有将它定义为停止训练的条件。

重复训练语料的边际收益与有效词元数

前面的推导以实际处理的词元数 DDD 衡量数据量。若只有 UUU 个不重复的语料 token，训练 KKK 轮共处理 D=KUD=KUD=KU 个 token，但第二轮及以后反复读取的是同一批语料，其效果未必等同于相同数量的新数据。

每次重复训练仍需执行相同的矩阵乘法，总成本约为 6NKU6NKU6NKU。重复次数增加后，变化的是额外计算能够换来多少验证损失的下降。Muennighoff 等用有效数据量描述这个衰减：

RD=K−1,Deff=U+URD∗(1−e−RD/RD∗).R_D=K-1,\qquad D_{\mathrm{eff}} =U+UR_D^*\left(1-e^{-R_D/R_D^*}\right).RD​=K−1,Deff​=U+URD∗​(1−e−RD​/RD∗​).

第一轮按 UUU 记满，后面重复的边际收益逐渐降低，衰减常数 RD∗R_D^*RD∗​ 由实验估。论文还给超过数据配比需要的模型规模构造了 NeffN_{\mathrm{eff}}Neff​，再代回损失函数。Scaling Data-Constrained Language Models §3

对实际处理量 DDD 求导：

∂Deff∂D=e−(K−1)/RD∗.\frac{\partial D_{\mathrm{eff}}}{\partial D} =e^{-(K-1)/R_D^*}.∂D∂Deff​​=e−(K−1)/RD∗​.

这个导数给出了重复训练的边际收益：在当前轮次再处理一个 token，按该拟合函数相当于增加多少有效 token。在 K=1+RD∗K=1+R_D^*K=1+RD∗​ 处它还有 e−1e^{-1}e−1，没有突然失效；边际掉一半的位置是 1+RD∗log⁡21+R_D^*\log21+RD∗​log2。

公开拟合代码中的有效数据量与参数量换算

datablations 的固定 notebook 让这件事落到代码上。普通曲面先把正系数参数化为 A=ea,B=eb,E=eeA=e^a,B=e^b,E=e^eA=ea,B=eb,E=ee，最后的 eee 是对数参数，然后算：

pre_lse = torch.stack([a - alpha*torch.log(inp[:, 0]), b - beta*torch.log(inp[:, 1]), e.expand((inp.shape[0]))])
post_lse = torch.logsumexp(pre_lse, dim=0)
huber_loss = torch.nn.functional.huber_loss(post_lse, torch.log(inp[:, 2]), delta=1e-3, reduction='none')

将拟合参数恢复到原始尺度后，模型预测的损失为

参数与数据的交互效应及可加损失模型的检验

将重复语料换算为有效数据量后，损失仍由参数项与数据项相加。由于公式将参数项与数据项写成简单相加的形式，没有引入交互项，因此可以直接检验一个推论：对两个唯一数据预算 U1<U2U_1<U_2U1​<U2​，

L(N,U1)−L(N,U2)=B(U1−β−U2−β),L(N,U_1)-L(N,U_2) =B(U_1^{-\beta}-U_2^{-\beta}),L(N,U1​)−L(N,U2​)=B(U1−β​−U2−β​),

等式右侧与模型参数量 NNN 无关。按这一假设，即使把模型换大，两种数据预算对应的损失之差也应保持不变。

如果观测到的损失差随模型规模系统性变化，重新估计五个系数也无法消除矛盾，需要允许参数项与数据项发生交互。《Data-Constrained Language Model Pretraining: Improved Regularization and Scaling Laws》研究的就是这个。作者在约 72M 到 1.4B 的五档规模上，分别用 100M、200M、300M、400M 唯一 token，凑出 20 个 DCLM 基线点；训练在八张 80 GB H100 上跑，上下文 2048，轮数和正则化都调过。原论文 §2、§4、附录 A 到 B

这里固定的是不重复语料的数量，并允许模型充分训练，要求解的是在这种条件下能达到的最低损失。它与前面固定训练 FLOPs 的问题有不同的约束。作者提出的 SoftQ 形式为

L(N,U)=E+(ANρ+BUρ/(1+α))α/ρ.L(N,U)=E+ \left( \frac A{N^\rho} +\frac B{U^{\rho/(1+\alpha)}} \right)^{\alpha/\rho}.L(N,U)=E+(NρA​+Uρ/(1+α)B​)α/ρ.

这里的 α,ρ\alpha,\rhoα,ρ 属于新模型，不能拿去和 Chinchilla 的参数混用。把括号里两项记作 x,yx,yx,y、外层指数记作 qqq，则

∂(x+y)q∂y=q(x+y)q−1.\frac{\partial(x+y)^q}{\partial y}=q(x+y)^{q-1}.∂y∂(x+y)q​=q(x+y)q−1.

只要 q≠1q\ne1q=1，参数项 xxx 就会影响继续增加数据能够改善多少损失。相比之下，纯加性表达式要求数据项的边际作用独立于参数量。

左图按论文附录表 12 的五个 400M 唯一 token 留出点重算：在 100M 到 300M 上拟合后，可加式预测 RMSE 0.0310635，SoftQ 0.00595494。右图用全网格拟合的舍入系数，是另一组公式比较：100M 和 400M 的数据差在 SoftQ 里从约 0.258 涨到 0.438，可加式只能给出约 0.350 的水平线。

五个相邻规模的留出点支持这项局部结构改进，从 1.4B 外推到几百 B 没有验证。也不能将已经对训练轮数优化过的曲面直接代回 6ND=C6ND=C6ND=C：训练量在构造曲面时已经被优化掉了。

这项研究还使用了 masked-input regularization，在干净输入的下一 token 损失之外加一项遮蔽输入的辅助损失。它提高了对有限语料的利用率，同时需要额外计算。因此比较数据效率时，需要同时报告固定语料下的损失改善，以及为取得这一改善增加的 FLOPs。

计入累计推理成本的模型规模选择

前面的最优解把预算都用来描述训练。模型若要长期部署，选型还取决于训练结束后一共需要处理多少推理请求。

Llama 3 的 405B 接近作者估的训练算力最低点，小模型则被有意训得更久。继续给小模型加数据，可能已经不如把同样的训练算力投给更大模型；可一旦小模型达到了需要的质量，往后每个请求都能少算一点。Llama 3 §1、§3.2.1

Sardana 等将模型生命周期内的推理成本纳入选型目标。Beyond Chinchilla-Optimal §2 为了比等质量的配置，先固定目标 loss 为 ℓ\ellℓ，设生命周期累计推理 token 为 III：

min⁡N,D 6ND+2NIs.t.L(N,D)=ℓ.\min_{N,D}\ 6ND+2NI \quad\text{s.t.}\quad L(N,D)=\ell.N,Dmin​ 6ND+2NIs.t.L(N,D)=ℓ.

成本式的第一项是一次性的训练开销，第二项会随模型部署后的累计使用量增加。沿可加损失曲面求解，可得到给定参数量时达到同一损失目标所需要的数据量：

D(N)=(Bℓ−E−AN−α)1/β,N>(Aℓ−E)1/α.D(N)= \left(\frac B{\ell-E-AN^{-\alpha}}\right)^{1/\beta}, \qquad N>\left(\frac A{\ell-E}\right)^{1/\alpha}.D(N)=(ℓ−E−AN−αB​)1/β,N>(ℓ−EA​)1/α.

需求特别大的一端推荐了极长训练，那正是损失外推最先失效的地方。Sardana 等训了 47 个 150M 到 6B 的 MPT 模型，用不重复的网页和代码数据；10,000 token/参数这种极端比例只在 150M 上试过，大模型没有完整覆盖。他们还发现，按常规训练比例拟合的曲线会高估极长训练的收益。同文 §3 到 5

这个推导说明，累计推理量足够大时，额外训练较小的模型可能降低总成本。但具体配置往往落在极长训练区，仍要验证损失外推是否成立；若同时受不重复语料的数量限制，还须将前面的有效数据量重新代入。

要把计算量换算成实际服务费用，还需要知道目标设备上的有效吞吐。prefill 一次处理输入，decode 逐 token 生成，两者 FLOPs 相同也可能因为批处理、KV cache 和带宽限制跑出不同利用率。更贴近部署的写法是

Cost=ctrain(N,D)+Q E[cprefill(N,P)+cdecode(N,P,T)],\mathrm{Cost} =c_{\mathrm{train}}(N,D) +Q\,\mathbb E[ c_{\mathrm{prefill}}(N,P) +c_{\mathrm{decode}}(N,P,T)],Cost=ctrain​(N,D)+QE[cprefill​(N,P)+cdecode​(N,P,T)],

QQQ 是请求数，P,TP,TP,T 是输入输出长度。这些成本函数都要在目标硬件、并行配置和延迟要求下测量。例如缩小模型后，如果权重刚好能由单卡容纳，部署所需的设备数就可能改变，服务费用也就不会按节省的 FLOPs 简单换算。

固定任务质量下的采样、验证与修订预算

即使任务数量固定，总推理量 III 也会随作答策略变化。同一道题可以只生成一次答案，也可以由验证器从多个候选中选择，或让模型在首答的基础上继续修订。策略决定花多少 token，同时改变答对的机会。

把这套策略记作 π\piπ，目标就变成

max⁡N,D,πEx[Score(x;N,D,π)]s.t.6ND+Q Ex[c(x;N,π)]≤Ctotal.\max_{N,D,\pi} \mathbb E_x[\mathrm{Score}(x;N,D,\pi)] \quad\text{s.t.}\quad 6ND+Q\,\mathbb E_x[c(x;N,\pi)] \le C_{\mathrm{total}}.N,D,πmax​Ex​[Score(x;N,D,π)]s.t.6ND+QEx​[c(x;N,π)]≤Ctotal​.

这个目标显式纳入了推理策略。预训练交叉熵之外，还需估计不同采样预算下出现正确候选的概率，以及验证器从中选对的概率，才能评价策略在任务上的效果。

Snell 等在 MATH 的 12k 训练题、500 测试题划分上，用训过修订或验证能力的 PaLM 2-S* 比较顺序修订和候选搜索，不同难度下合适的预算分配不一样。估计难度用的每题 2048 个样本本身也有成本，论文没把这项成本全部算进主要效率分析。原论文 §3 到 4

当容易题的成功率已接近上限时，候选增加十倍也可能几乎没有改善。反过来，如果极难题在现有策略下几乎从不产生正确解，评价器也无法从这些候选中选出正确答案。要分配推理预算，就得用部署时实际可见的信息估计哪些请求能从下一次计算中获益。

采样、选择与修订改变的是部署后的推理成本。回到开头的 7B 与 70B，如果只关心固定训练 FLOPs 下的验证损失，可以沿 Chinchilla 曲面比较两种配置。一旦还要考虑不重复语料是否充足、模型会被调用多久、每个请求生成多少候选，原先的训练配比就只能作为总成本计算中的一项。关于几种推理策略的对照，见自纠、候选选择与过程监督。
