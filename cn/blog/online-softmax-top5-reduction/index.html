逐行 Softmax 与 Top-5 融合：分块状态合并与两次 CUDA 启动

每行只返回得分最高的五个位置及其概率，但分母仍包括所有列的贡献。每个线程块用 48 字节保存五组候选、局部最大值与指数和，下一次启动就能合并候选并写回概率，完整算子由四次 CUDA 启动减为两次。

这个算子在每行找出得分最高的五个位置，返回它们的列号和它们在整行 Softmax 中的概率。因此我们可以在比较名次时淘汰第六名，却仍要保留它对分母的贡献。少算这一个数，连第一名的概率也会改变。

例如，取一行分数 [0,ln⁡2,0,ln⁡4,0,ln⁡2][0,\ln 2,0,\ln 4,0,\ln 2][0,ln2,0,ln4,0,ln2]。列号从 0 开始，取指数后的权重依次是 [1,2,1,4,1,2][1,2,1,4,1,2][1,2,1,4,1,2]。分数相等时，列号小的排在前面，因此结果的列号是 [3,1,5,0,2][3,1,5,0,2][3,1,5,0,2]；列 4 在最后一个名额上落选。若计算概率时一并丢弃列 4 的权重，分母就会从 11 降到 10，第一名也会从正确的 4/114/114/11 变成 4/104/104/10。

48 字节分块状态中的归一化参数与五个候选

对一个分块来说，只要已有五个分数排在某一项之前，那一项就进不了整行的前五名。线程块因此只需保留五组分数和列号。为了用整行的分母计算这五个位置的概率，线程块还要记录本块的最大分数和按该最大值缩放的指数和。四类数据合在下面这份状态里。

constexpr int top = 5;
struct State {
    float m, d, value[top];
    int index[top];
};
static_assert(sizeof(State) == 48);

图 1　每格 4 字节。m 是当前最大分数，d 是以该最大值为基准的指数和。五个原始分数连续存放，后面才是五个列号。第 j 个分数 value[j] 对应列号 index[j]。

把示例行从列 2 后面截成两段，左段以最大值 ln⁡2\ln 2ln2 为尺度，移位后的指数和为 2。右段的最大值是 ln⁡4\ln 4ln4，指数和为 7/47/47/4。合并时取较大的最大值作为公共尺度，因而要将左段的分母乘以 eln⁡2−ln⁡4e^{\ln 2-\ln 4}eln2−ln4。换算后左边贡献 1，加上右边的 7/47/47/4，得到 11/411/411/4。第一名在这个尺度下的权重为 1，除以 11/411/411/4，刚好还原出 4/114/114/11。这就是分块可以各自扫描输入的原因。在线归一化及其在 Top-K 中的应用

从线程候选归并到整行 Top-5 概率

第一次启动 global_part<true,false> 时，每个线程块负责本行的一段。块内的 partial<true> 让各线程从不同列起步，每次前进 blockDim.x 列。线程以负无穷和零初始化最大值与指数和，随后按下面的规则把读到的分数 v 加入自己的状态。

if (v > s.m) {
    s.d = s.d * expf(s.m - v) + 1;
    s.m = v;
} else {
    s.d += expf(v - s.m);
}
insert(s, v, i);

如果 v 超过旧最大值，我们要先把 s.d 换到新的尺度，再为 v 加上 1。其他分数直接贡献 expf(v - s.m)。代码在更新分母以后才用 insert 判断第 i 列能否进入前五名，这个顺序保证了落选分数也参与归一化。遇到并列分数时，各级归约都保留原始列号较小的一项。

每个线程先把自己的局部状态写入共享内存，同一线程块内再将这些状态两两归约，得到该块的一份部分结果。不同块的结果在第二次启动时才会合并。combine<true> 合并两份非空状态时，以较大的最大值为公共尺度，将两份指数和换算到同一尺度后相加。候选列表保存的是原始分数，可以按原来的排序规则直接归并。

c.m = fmaxf(a.m, b.m);
c.d = a.d * expf(a.m - c.m) + b.d * expf(b.m - c.m);
int u = 0, v = 0;
for (int j = 0; j < top; ++j) {
    bool left = before(a.value[u], a.index[u], b.value[v], b.index[v]);
    c.value[j] = left ? a.value[u] : b.value[v];
    c.index[j] = left ? a.index[u++] : b.index[v++];
}

u 和 v 分别指向左右两个有序列表里尚未取走的首项。代码取分数较高的一项；若分数相同，则取原始列号较小的一项。选中项的分数和列号一起写入结果，只有这一侧的游标向前移。列表已有五项时即可结束。线程块完成归约以后，由线程 0 把这份 State 写入全局内存。

第二次启动 finish<true> 时，每行只由一个线程收尾。它从全局内存取出本行的两份或四份状态，再用同一个 combine 合成最终状态。最后逐项写出列号，概率按 expf(s.value[j] - s.m) / s.d 计算。开头那个落选的第六名没有输出列号，它对分母的贡献则一直保存在 s.d 中，参与了这里的每一次除法。

在线归一化将四次 kernel 启动缩减为两次

四次启动的基线先分别求分块最大值，再合并成整行最大值。直到这个值传回来，分块才能用统一的尺度重扫分数，生成候选和指数和，交给最后一次启动合并。在线版本把各自的尺度连同候选交给下一轮，因此第一次扫描就能写出分块状态，第二次启动可以直接合并并写回结果。

图 2　每个方框代表一次 CUDA 启动。四次启动的基线必须等整行最大值算完，才能重新扫描各块。在线版本让每块先用自己的最大值计算，在最终合并时统一尺度。

以 32 行、每行 32,768 列为例，FP32 输入共 4 MiB。按输入索引统计，基线扫描这 4 MiB 两遍，在线版本只读一遍。每行分四块时，两种路径最后都合并 128 份状态，按结构体大小合计 6 KiB。另行采集的 Nsight Systems 时间线也在这一形状上看到四次与两次启动。

两次启动与四次启动的整行 Top-5 耗时

在 RTX 5070 Laptop GPU 上，我们固定输入为 32 行、每行 32,768 列，每行仍分四块，从归约开始计到五个列号和五个概率全部写回设备。在重复使用输入地址时，四次启动约用 72 µs，两次启动约用 54 µs。两边都改用轮换地址后，各自耗时增加，在线版本依然较快。

图 3　比较的是两种完整算子的设备耗时，横坐标为四次启动耗时除以两次启动耗时。虚线表示耗时相等，线段给出该条件的 95% 区间。

24 组条件下，两次启动都更快，配对加速比从 1.135× 到 1.535×。这个差额同时计入少扫描一次输入、少启动两个 kernel 的收益，以及重标定多做指数运算的成本。能够合并这两步，靠的是 48 字节状态保留了两种信息：五组候选记录名次，局部最大值和指数和则保留整行概率所需的分母。

计时口径、正确性校验与画图数据

实验使用 CUDA 13.1，分数和指数和均为 FP32。计时前我们预先分配输入和工作区。各 kernel 以每块 128 个线程在同一条 CUDA 流上常规启动，计时从第一次归约前开始，到列号和概率都写回设备为止。行数取 1、32、512，列数取 4,096、32,768，每行分两块或四块。重复地址组先预热同一输入，轮换地址组在四份独立生成的输入视图之间轮转，并在计时前另访问至少 48 MiB 的数据。同一对观测中的两种算子读同一份输入。

每种配置启动八个独立进程，每个进程贡献 20 对观测。区间用 4,000 次分层自助抽样求得，先抽进程，再在对应进程内抽成对观测。表中两列时间是不同实现各自的中位数，加速比取每一对四次启动耗时与两次启动耗时之比的几何平均数。

CPU 参考实现对原始分数做稳定降序排序，并用 FP64 计算整行分母。两条全局内存路径在 72 组正确性检查中都得到完全相同的参考列号；测试覆盖每块 128 或 256 个线程、分数并列、最大值落在末块、指数下溢。概率与参考值的最大绝对误差小于 1.3×10−71.3\times10^{-7}1.3×10−7。
