注意力汇聚与输出门控：初始词元、零值槽位与门控缩放

StreamingLLM 保留初始词元的键和值，使这些位置继续参与注意力归一化。若其中一个位置的值为零，它能按同一比例缩小其余位置的贡献。对给定查询，这一效果可以用标量门控重现。若各通道采用不同的门控系数，输出连方向也会改变。

假设一个注意力头（attention head）里每个位置的值都是标量 1。查询无论偏向哪个位置，softmax 的权重之和都是 1，加权结果自然也是 1。若希望这个头只向残差分支写入 0.1，单靠在这些值之间重新分配权重就做不到。

一种做法是增加一个值为零的位置，让它占去九成概率，剩下的值合起来便贡献 0.1。也可以沿用原来的概率，在加权求和之后乘以 0.1。这个例子里两种做法的输出相同，而当查询改变，或不同通道需要不同增益时，它们的差别就会显现出来。

注意力汇聚位置（attention sink）指在不同查询中反复获得大量注意力概率的位置。上例特意让它的值为零，以便只观察它占用概率所产生的影响。实际模型是否形成这样的汇聚位置、对应值向量朝哪个方向，都需从模型本身检验。这里的 CPU 实验使用作者的缓存类和注意力前向函数来核对机制。

注意力头的输出范围与值向量的凸包

设当前位置的隐藏状态为 xix_ixi​，由它投影得到查询（query）qiq_iqi​。历史位置分别提供键（key）kjk_jkj​ 和值（value）vjv_jvj​。暂时略去位置编码与掩码，一个注意力头的计算可以写成

sij=qikj⊤dh,pij=esij∑kesik,ui=∑jpijvj.s_{ij}=\frac{q_i k_j^\top}{\sqrt{d_h}}, \qquad p_{ij}=\frac{e^{s_{ij}}}{\sum_k e^{s_{ik}}}, \qquad u_i=\sum_jp_{ij}v_j.sij​=dh​​qi​kj⊤​​,pij​=∑k​esik​esij​​,ui​=j∑​pij​vj​.

dhd_hdh​ 表示每个头的宽度。各个头先得到自己的输出 uiu_iui​，拼接以后经过输出投影 WOW_OWO​，再写入残差分支。注意力热图通常展示归一化的概率 ppp。要解释某个位置的实际作用，还需区分产生这个概率的分数 sss，以及将它乘以值后得到的向量 uuu。

这些概率满足 pij≥0p_{ij}\ge0pij​≥0 且总和为 1，所以 uiu_iui​ 只能落在所有 vjv_jvj​ 的凸包内。凸包是这些向量用非负权重、权重总和为 1 混合出来的区域。某一维的所有 value 都是 1，这一维的输出就只能是 1；中间多一个零向量，原点也进入凸包，输出才有缩小的余地。

真实模型还有别的办法：不同 value 可以互相抵消，WOW_OWO​ 能改方向和尺度，残差分支也能和其他子层一起调整。

StreamingLLM 观察到若干已训练模型会反复给初始位置分配较大注意力，并把这件事与概率归一化、初始位置对后续 query 的持续可见性联系起来。When Attention Sink Emerges 进一步考察了训练与架构条件，在其设置里，sink 更像一个吸收多余概率的 key bias，归一化方式会影响它如何形成。

初始位置对所有后续查询可见，这给了它吸收概率的机会。它是否真的成为 sink，要看训练出来的查询和键如何共同决定概率。至于被分配的概率会给后续计算带来多大影响，还取决于对应的值向量。

移除注意力汇聚位置后的概率重归一化

固定查询，让 aaa 表示某个候选汇聚位置的概率，vsv_svs​ 表示它的值向量，μ\muμ 表示其余位置单独归一化后的加权输出。若仍保留这个位置，完整的输出为

图中的放大倍数由上述标量例子计算而来。为核对一般形式，我另取三个随机种子、四种值向量维度和八种概率做了 96 组 FP64 检查，最大绝对残差为 8.88×10−168.88\times10^{-16}8.88×10−16。这里检验的是归一化公式，训练好的语言模型中实际会放大多少，还取决于它的键和值。

删去这个位置会同时产生两种影响：它原来的值贡献消失，留下的内容又因分母变小而被重新放大。因此，即使被删位置的值接近零，只要它原来的概率足够大，输出也可能大幅变化。这个等式只描述一个固定查询，下游层的输入也会随之改变，各层的差值因而不能直接相加。

StreamingLLM 对初始 KV 与近期窗口的缓存分配

自回归生成不断增加历史 KV。固定容量的滑动窗口装满后，每加入一个新位置就会淘汰最早的位置。如果初始位置已经成了 sink，第一次淘汰它时，同一行里的其他内容就会按上节的公式被重新放大。

StreamingLLM 将固定容量分给两段历史：前段永久保留少量初始词元的 KV，后段作为滑动窗口保存最近的 KV。容量用满时，两个区间之间的位置直接被淘汰，因此无需逐个估计旧词元的保留价值。

作者在 StartRecentKVCache 中用下面的切片保留这两段键向量。

torch.cat(
    [
        self.k_slice(k, 0, self.start_size),
        self.k_slice(k, seq_len - self.recent_size, seq_len),
    ],
    dim=self.k_seq_dim,
)

值向量使用相同的切片。作者的默认配置保留开头 4 个位置和最近 512 个位置。为了逐项观察何时淘汰一个词元，我将总容量固定为 16，比较全部留给滑动窗口的 0+16，以及为开头两个词元预留位置的 2+14。两种策略都在总容量用满后才开始淘汰。

我把编号 0–63 的张量依次传给作者的缓存类，在 0+16 和 2+14 两种配置下共调用 128 次，逐次核对保留的编号。随后用同一批编号去索引两种构造的注意力输入，一组检验分母是否稳定，另一组检验目标词元还能保留多久。

缓存截断后的 RoPE 位置重映射

保留哪几个 token 也决定了 RoPE 如何计算它们的相对位置。RoPE 给查询和键施加依赖位置的旋转，删去中间一段以后，留下的 token 在紧凑缓存里有了新的编号。实现需要在正确的时刻用这些编号计算旋转。

在作者的 Llama 位置迁移实现 里，缓存先拿到未旋转的 key，用于本次 Attention 的 key 才按连续位置旋转：

past_key_value = (key_states, value_states) if use_cache else None

key_position_ids = torch.arange(kv_seq_len, device=position_ids.device).unsqueeze(0)
key_states = apply_rotary_pos_emb_single(key_states, cos, sin, key_position_ids)

例如，缓存里保留的原始词元编号为 [0, 1, 2, 3, 6, 7, 8]，而下一次查询来自 token 9。按紧凑缓存重新编号后，初始词元与近期词元之间的相对距离已经缩短，RoPE 计算点积时使用的相对旋转也会改变。

若缓存里存的已经是按旧位置旋转过的 key，再按新位置旋转一次就是叠加旋转。先缓存未旋转的 key、让本次计算自己按当前位置生成旋转，是这段代码的关键顺序。前面那组 CPU 实验只跑了裁剪类和构造 Attention，没有跑完整 Llama 的 RoPE 迁移，也没有困惑度测量。

SDPA 输出的逐通道 sigmoid 门控

保留初始 KV 是在 softmax 的候选集合内保留一个位置，另一条路径则直接控制已经算出的头输出。Gated Attention 研究的一种门控位置，就在缩放点积注意力（SDPA）的输出之后、输出投影之前。

在 Qwen3 的解码层中，输入隐藏状态先经过 RMSNorm，归一化后的张量才传入自注意力。用 xix_ixi​ 表示其中第 iii 个位置的输入，查询和门控投影都从这个 xix_ixi​ 计算。SDPA 得到头输出 ui=∑jpijvju_i=\sum_jp_{ij}v_jui​=∑j​pij​vj​ 后，才乘上由门控投影产生的系数。Qwen3 解码层的调用顺序

gi=σ(xiWG),u~i=ui⊙gi.g_i=\sigma(x_iW_G),\qquad \widetilde u_i=u_i\odot g_i.gi​=σ(xi​WG​),ui​=ui​⊙gi​.

逐头门控（headwise gate）为整个头生成一个系数，逐元素门控（elementwise gate）为每个通道分别生成系数。门控乘在 SDPA 输出上时，本次 Softmax 的 pijp_{ij}pij​ 已经确定。缩放后的头输出再拼接起来，通过输出投影 WOW_OWO​。

作者的 Qwen3Attention 固定源码 把 gate 投影和 query 投影放在同一个 q_proj 里。逐元素门控版的投影宽度是普通查询的两倍。实现再按 KV 组拆出查询和门控张量，其中门控张量的最终形状为 [batch, length, heads, head_dim]。

将两条支路共用一次线性投影，只改变了生成它们的计算方式。拆出的查询照常参与 QK 点积，而对应的门控系数直到 SDPA 输出就绪后才使用。

attn_output = attn_output.transpose(1, 2).contiguous()

if self.headwise_attn_output_gate or self.elementwise_attn_output_gate:
    attn_output = attn_output * torch.sigmoid(gate_score)

attn_output = attn_output.reshape(bsz, q_len, -1)
attn_output = self.o_proj(attn_output)

代码位置同时决定了广播方式和通道含义。把逐通道 gate 挪到 WOW_OWO​ 后面，一般拿不到同样的结果：输出投影已经把通道混合过，矩阵乘不能和一个任意对角缩放交换顺序。

为了单独检查门控对这一轮前向的影响，我从固定版本的源码提取 eager 函数，在 CPU 上配上小型投影层。Q/K/V 保持一致，分别加 headwise 和 elementwise gate，序列长度 1、7、16，种子 0、17、42，共 18 组对照。返回的注意力概率差值全为零；输出与「原 SDPA 输出乘对应 gate」的独立重构也完全一致。

在这些前向对照中，Q/K 和已有权重都已固定，因此我们能验证门控乘法改变的是哪个张量。原论文 §4讨论的则是训练后汇聚减弱的现象，此时 Q/K 与中间激活也随训练改变，作者将它与因查询和注意力头而异的输出稀疏性联系起来。单次前向无法验证这种训练结果，而且在这份 eager 实现里，施加门控时 QK 与 PV 都已完成。

固定查询下零值汇聚位置与标量门控的等价条件

开头的例子给零值 sink 分配了 90% 的概率，普通位置的总贡献便从 1 降到 0.1。这和乘以标量门控 0.1 的结果相同，因为固定查询后，零值 sink 会按同一比例缩小所有普通位置的贡献。我们可以从这个比例直接求出与给定标量 gate 匹配的 sink 分数。

令普通位置的指数和为 Z=∑jesjZ=\sum_j e^{s_j}Z=∑j​esj​，它自身归一化后的输出是 μ\muμ。加一个 logit 为 ccc、value 为零的 sink：

usink=ZZ+ecμ.u_{\mathrm{sink}}=\frac Z{Z+e^c}\mu.usink​=Z+ecZ​μ.

令缩放后的输出等于标量门控的 gμg\mugμ。在 0<g<10<g<10<g<1 时，所需的汇聚分数为

c=log⁡Z+log⁡1−gg.c=\log Z+\log\frac{1-g}{g}.c=logZ+logg1−g​.

g=0g=0g=0 与 g=1g=1g=1 对应无限 logit 的极限。关键在于匹配值里出现了 ZZZ：普通 key 和 query 一变，需要的 sink 分数也跟着变。

统一平移内容分数会改变汇聚位置的概率

给所有普通 logits 加上同一偏移 bbb 时，它们之间的概率比例保持不变，归一化的输出仍是 μ\muμ，但普通位置的指数和 ZZZ 会增大或缩小为原来的 ebe^beb 倍。固定分数的 sink 由此获得不同的概率，输出幅度随之变化，而固定的输出 gate 仍乘以原来的系数。

图中的原始分数为 [−0.7,0.2,1.1][-0.7,0.2,1.1][−0.7,0.2,1.1]，values 的第一维都是 1，公共偏移从 −8 到 8。固定 c=0c=0c=0 的 sink 输出从接近零移向 1，固定 g=0.2g=0.2g=0.2 的输出一直是 0.2；按上式逐输入算出的匹配 sink 与 gate 的最大差是 1.94×10−161.94\times10^{-16}1.94×10−16。

真实 sink 的分数本来会随 query 变，不一定是常数。但一个固定 key 与 query 的点积，能不能对所有输入都实现 log⁡Z+log⁡((1−g)/g)\log Z+\log((1-g)/g)logZ+log((1−g)/g)，仍然需要证明。ZZZ 聚合了所有普通 key 的指数分数。逐个输入手算一个 ccc，不构成两种参数化之间的普遍等价。

逐通道门控可以改变输出方向

即使查询固定，零值 sink 也只能按同一比例缩放所有通道。逐通道 gate 可以为不同坐标指定不同的缩放系数。普通输出若是

μ=(1,1.118615),\mu=(1,1.118615),μ=(1,1.118615),

任意标量 gate 都落在 gμg\mugμ 这条线上。逐通道系数 (0.2,0.8)(0.2,0.8)(0.2,0.8) 给出的却是

μ~=(0.2,0.894892).\widetilde\mu=(0.2,0.894892).μ​=(0.2,0.894892).

逐通道缩放后的点已经偏离原方向。即使选取最佳拟合标量（约 0.533487），它与标量缩放直线之间仍有约 0.447317 的欧氏距离。

普通 value 与输出投影可以合并成同一个矩阵。逐通道 gate 引入一个依赖 query 状态的对角矩阵 DiD_iDi​ 之后，合并项变成

不同 query 就能对同一组 value 通道作不同取舍。这里加入的是输入相关变换；完整 Attention 早已通过 Q/K 和 Softmax 非线性地依赖输入，不能说门控才第一次引入非线性。对固定 query，这个乘积的秩仍然不超过 head 宽度，也没有因为多一个对角矩阵就突破秩上限。

固定长度的 StreamingLLM 缓存保留开头和最近的 KV默认 4+512，文中的小实验是 2+14 或 0+16

对一个给定的查询，可以算出与标量门控等效的零值 sink。 可一旦换查询，所需分数就取决于整行的指数和；换成逐通道门控，连输出的方向都可能改变。如果所有值向量的凸包本来就包含原点，它们也有机会相互抵消。有限分数给每个未遮蔽的位置严格为正的权重，原点能否恰好取得仍取决于这些向量和权重。

StreamingLLM 保留初始词元的 KV；当训练已经使这些位置成为汇聚位置，后续查询便能继续访问它们。Qwen 的门控模型则可以直接调节写入残差分支的幅度，训练后观察到的汇聚也可能更弱。缓存策略决定哪些位置进入下一次注意力计算，门控作用于这次计算的输出，两者可以同时使用。

作者函数检查用 CPU PyTorch 2.14.1；曲线用 Python 3.13.5、NumPy 2.4.4、Matplotlib 3.11.0。没有下载模型权重、跑 GPU 基准或训练语言模型。StreamingLLM 是 MIT 许可；Gated Attention 根目录为 MIT，节选文件保留 Apache-2.0 许可头，快照保留两种归属信息。

为直接比较头输出，门控对照将 RoPE 设为恒等旋转，将 WOW_OWO​ 设为恒等映射，保留因果掩码并关闭 dropout。投影和乘法用 FP64，Softmax 按作者实现转成 FP32 再转回来。实验分别运行九次基础前向和十八次带门控前向，只覆盖这一注意力模块。
